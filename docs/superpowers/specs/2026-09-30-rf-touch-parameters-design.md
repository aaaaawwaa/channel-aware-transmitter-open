# RF 触摸参数录入接续设计

背景：session `e5d8a816-5399-4ecd-a7e7-33f96b6d78de` 最后的用户选择为“路径一”，复用现有触摸数字键盘；当前用户请求接续该进度。本设计将其落为既有面板功能，不新增参数文件或默认射频值。

## 范围与界面

实际源码在 `<LOCAL_PATH>

“接收”页新增“RF参数”子页，保持七个主导航不变。复用 ValueRow / Keypad / 真实按下抬起输入路径。左列本振 Hz、采样率 Hz、衰减 mdB、PHY模式；右列 RX/TX 带宽 Hz、IDELAY 开关与 tap。空字段显示未填，键盘起始为空；不从只读快照或 AWG 草稿隐式带入参数。清空草稿只清本地 RF 参数。

编辑和清空不发送网络命令、不改硬件；初始化/配置依然需要二次确认。编辑接受的新参数会撤销待确认动作，避免确认的参数发生变化。参数子页与概览共享同一 RF 控制出口，确认期间仍保留停止入口。

## 参数契约与数据流

daemon 的 `rf.init` 必填 LO、采样率、衰减，`rf.configure` 还必填两个带宽。面板要求两种请求显式填写 PHY模式，configure 还显式填写 IDELAY：省略模式会默认0=2R2T，省略 IDELAY 会写0/0，不是保持原值。面板采用比 daemon 更严格的完整草稿条件，避免隐含模式切换或延迟清零。模式0=2R2T/1=1R1T；模式切换需要重新初始化，configure 不会主动切换模式。当前 daemon 使用 rf_proto_arg_int/get_uint，正整数字段的协议上限是 INT32_MAX=2147483647；这只是传输表示范围，不宣称 AD9361 能接受所有频率/速率。衰减 0..89750 mdB，开关整数 0/1，tap 0..31；错误输入不得替换已接受值。

UiApp 保存参数并提供只读副本、计划与缺失原因。UiView 只读写本地模型。`pynq_status._rf_control_action` 再取完整计划，缺失时本地拒发，成功时传给 `RfStatusWorker.control(..., args)`；worker/client 保留广告能力和握手门禁。确认的是草稿，daemon 响应仍是实际操作结果。

## 验证与边界

先用失败测试钉：真实触摸录入全部字段、空值/越界/取消、不发送副作用、清空、编辑撤销确认、停止可达、字段范围、签名刷新、参数到 worker 的准确传递及缺参拒发。再运行 PYNQ/RF/host 相关回归。

渲染未填、已填、键盘与错误状态，检查矩形、文字、命中、板上字体。板上确认当前发布和服务后，只由唯一 Overlay 所有者装载；测试工具绘制到内存，不调用第二个 Overlay。

在释放版本前验证生产调用链的操作耗时与响应。现有 client 默认超时 0.75 秒，是否足够 init/configure 尚无本轮证据；如实测失败，先定位并补回归，不能只凭离线 UI 通过宣称硬件操作可用。最终记录区分离线、发布内和物理 RF 测量；不启动 TX/RX 数据路径。

## 审查与实测后的补充

已实测发布内 client 初始化在0.7517秒超时，但8秒后板上READY。因此不能保留同步GUI回调或仅放大读取超时：init/configure 使用独立20秒期限，轮询/短控制仍用0.75秒；client的网络事务串行，避免轮询在长操作时产生假超时。worker 后台执行控制，主循环只提交草稿副本并接收真实完成结果，不把“排队”当作成功。最多一个正在执行的控制和一个停止请求，不接受更多积压。等待期间面板明确显示正在等待硬件响应，并保持停止入口；停止在当前 daemon 操作结束后执行，不声称可以中断 native init。状态过期仍正常显示，不伪造新的状态采样。

补测后台调用快速返回、参数副本、BUSY拒绝、停止排队、完成结果落地、长操作期间触摸、控制读超时与轮询期限分离，以及生命周期清理。UI完成之后再做生产调用与打包验收。

复审明确：执行期间禁用 RF 编辑和清空，避免键盘遮住停止；worker 的 take_frame 在同一锁下领取快照、完成结果和运行状态；两个快照生产者都经 _poll_once 的独立锁完成采样到发布，防止旧读数晚到覆盖新读数。状态快照锁不覆盖网络等待，显示线程因此仍快速返回。实测与最终报告见 `docs/reports/2026-09-30-rf-touch-parameters.md`。

不在本功能中做 reboot 重现、物理断电、历史积压批量提交或清理。这些仍按现有报告另行推进。
