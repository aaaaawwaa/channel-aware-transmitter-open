# HEADROOM 46 dB 余量：定义候选、测量方案与决策清单

**状态**：提案（`PROPOSAL`），2026-10-17。**不是合同、不是批准件、不是验收记录**；定义与阈值的决定权在产品所有者。
**范围**：本文件与 `evidence/rf-teaching/s2-headroom-margin-plan-2026-10-17/` 为唯一新增物。零 RF、零板卡接触、零授权/nonce 消耗、零产品代码/测试/封存件改动、零 `git commit`。
**一句话**：**"46 dB" 是衰减设置（`46000 mdB`），不是任何已被测量的余量**。当前证据支持的最强结论是：5 帧无 native rail，最坏帧码域峰值距名义满量程 **4.25 dB**，**窗口内 AGC 状态未观测**、每场景 **n=1**。

## 2. 候选定义 D1–D4

### 2.1 定义、单位、参考面、所需测量

| ID | 定义 | 单位 / 参考面 | 所需测量 | 阈值（待所有者定） |
|---|---|---|---|---|
| **D1** 码域余量 | `M = 20·log10(2048 / max(peak_abs_I, peak_abs_Q))`，全 8192 分量 | dB / **ADC 数字输出码**（AGC 模拟增益之后、数字增益关闭 `rf_core.c:257`、FIR 之后） | 既有 5 帧流程；**不改任何东西** | 3 / 4 / 6 / 10 dB（见 §2.3） |

### 2.3 D1 阈值 × 既有数据（决策关键：答案随阈值翻转）

| 阈值 | 判定 | 依据（最坏帧 4.25 dB；normal 6.92；OFF 14.45/16.63） |
|---|---|---|
| ≥3 dB | **PASS** | 5/5 通过，最小裕度 1.25 dB |
| ≥4 dB | **PASS（勉强）** | pulse 4.25，裕度 0.25 dB；n=1，等于没有裕度 |
| ≥6 dB | **FAIL** | pulse 4.25 与 narrowband 4.49 不达标（normal 6.92 达标） |
| ≥10 dB | **FAIL** | 三个 TX 开帧全部不达标 |

**这条表是本次提案的核心**：同一批字节，阈值取 4 dB 是 PASS、取 6 dB 是 FAIL。所以"46 dB 余量是否足够"在定义与阈值冻结之前**无法回答**；先冻结定义，才不会变成事后挑阈值。

> **更正（2026-10-17）**：本表与上句只说明"阈值不同结论不同"。D1 保留为**诊断指标**；本阶段**不把它变成 6 dB 硬门**，D1 数值也不是推进 46 dB 域或恢复 S2 主线的前置条件（顶部更正 3）。

## 3. 推荐路径（最小可行）

### 3.1 推荐

1. **把 D1 作为"当前域唯一可冻结的指标"**，并同时冻结它的三条附注：参考面在 AGC 之后、窗口内 AGC 状态 `NOT_OBSERVED`、每场景 n 必须写进结论。
2. **第一步只做三件事**，全部不改产品：

| 步 | 动作 | 成本 | 产出 |
|---|---|---|---|
| S1 | 冻结 D1 公式/单位/参考面/阈值（文档） | 0 | 一页定义，含 §2.3 的阈值选择 |
| S2 | 用已归档 5 帧做 **POST_HOC 打分**，标签必须写 `POST_HOC / 非验收` | 0 会话，<1 s | 4.25 dB（pulse）作为"当前工作点的码域余量" |
| S3 | **1 份新授权**跑 1 次同样的 5 帧会话（第二次重复），把 n 从 1 提到 2 | 1 授权/5 帧/~14 s RF + 人工接线确认 + 只读预检 | D1 的帧间一致性；一份可对账的新证据包 |

3. **不建议**把 D2 作为第一步：它需要 N 份授权（或一次产品变更），在定义与阈值未冻结前做，等于先花钱再问问题。

### 3.2 它不能回答什么（必须与结论一起读）

| 不能回答 | 原因 |
|---|---|
| 链路余量（可容忍多少额外衰减） | 衰减钉死、AGC 闭环未观测（U1/U3） |
| 模拟前端是否压缩、P1dB | 码域事件不等于压缩（U2） |

| 窄带失步的原因 | 独立问题（U5） |
| 是否可外推到其他 release/接线/会话 | n=1、单会话、单 release |

## 4. 测量方案（D1 + 重复；D2 作为可选延伸）

### 4.1 会话结构

| 阶段 | 内容 | 判据 |
|---|---|---|
| 初始化 | `headroom.begin`：`rf_core_init(46000…)` + `configure` + 读回 | ACK 的 `initializations==1`、`attempt_budget==5`（`2026-10-12` 设计:108）、`actual_rf` 过 `_fixed_rf_error`（`rf_headroom.py:399-437`） |
| 尝试 1–5 | 固定顺序；2/3/4 才开 TX；`settle_wait_us=0` | 每帧 `accepted=true`、`terminal=AWAIT_ACCEPT`、`rail_count` 与复算一致（`:507-515`） |
| 收尾 | 第 5 帧 `accept` 触发 close；或 `abort` | 关闭确认 + 独立只读安全读回（未布防/TX 关/RX 关） |
| 计算 | 下载后用 `s2-headroom-margin-offline-2026-10-17/work/analyze_margin.py` 复算 D1 | 与 header/receipt 的 `rail_count`、`iq_sha256` 三方对账 |

重复：**3 个会话（推荐）或 2 个（最低）**，每个会话独立 `session_id`、独立授权与 nonce；**不得**在同一 nonce 下补采。

### 4.2 每步判据与失败处置

| 情况 | 处置 |
|---|---|
| 任何原生门失败（能力/布防/begin/帧/关闭） | 会话停止、不重试、不补采（沿用 `rf_headroom.py:12-14` 的"一次即锁"不变量）；保留原 IQ 与拒绝原因 |
| native rail > 0 | 该帧 `CLIPPED`，D1 记 `0 dB`（或负值），会话终止；**不得**换帧重跑 |
| 证据错配（`rail_count`/`iq_sha256` 不符） | 该帧不计，整体 `NOT_ASSESSED`；这是代码本身会拒绝的条件（`:503-510`） |
| 窄带无同步但无 rail | **单独陈述**：D1 可算（码域），但不得用"无 rail"替代"可用"（`NOTES.md:145-154`） |
| D1 低于阈值 | 结论为 FAIL，**不是**"46 dB 不足"；只说明"该工作点码域余量 < 阈值" |

### 4.3 授权口径（硬约束：一次授权 = 一次会话）

| 约束 | 事实 | 后果 |
|---|---|---|
| `authorized_attempts` | 必须为整数 **5**，其它值直接拒 | 一次授权只能跑一次 5 帧会话 |
| `single_use` + 板端 nonce 账本 | 必须 `true`；nonce 出现即拒 | 不能复用、不能"补一帧" |
| 衰减 | 两侧都钉死 46000（K1） | **一次会话只能一档** |
| 接线确认 | 距运行 ≤12 h | 多会话需重新确认 |

> **更正（2026-10-17）**：本行"多会话需重新确认"不是现行规则——按 `docs/requirements/development-review-policy.md:47`，接线未变且在有效窗口内可引用原确认（顶部更正 2）。"≤12 h"是 HEADROOM runner 自身的硬窗口，不是"每会话必须重新确认"的要求。

⇒ **若要做 D2 的 4 档扫描**：4 份授权、4 次预检、4 次接线确认（≈4×14 s RF + 4×人工/预检开销）。若要在**一次会话内**扫档，必须改合同/原生面（§5）——本文件不提出也不实施这种改动。

> **更正（2026-10-17）**：本段前半句（"4 档扫描 = 4 份授权 + 4 次接线确认"）**不成立**：授权数量不改变衰减档位（两侧常量固定），4 份授权只能得到 4 次**同一 46 dB 档位**的会话；4 次接线确认也不是规则要求（顶部更正 1/2）。后半句仍然成立：**一次会话内扫档**必须改合同/原生面。

### 4.4 安全边界（沿用既有已审查口径，不新增授权面）

| 项 | 边界 |
|---|---|
| TX 功率/路径 | TX1→RX1 有线直连；内部 TX 衰减 ≥46 dB；不接天线、不做空口 |
| 单帧 | 4096 样点 / 60 MSPS = **68.27 µs**；每会话最多 3 个发射窗口 |
| 单会话 | 1 初始化 + ≤5 尝试；实测 RF 段 13.33 s（`receipt.json:94`） |
