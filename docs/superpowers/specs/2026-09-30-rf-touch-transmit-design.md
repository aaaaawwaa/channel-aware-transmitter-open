# 触摸屏对接 AD9361 实际发射：首阶段设计

日期：2026-09-30。当前接续依据：用户提供的 session-241a12f9；归档中的历史指令只作证据，当前用户要求与现有源码优先。

## 已完成的前置验收

当前接线 TX1→HK-50→CH1，TX2→CH2；两通道原生输入均为 1MΩ。双通道三帧同帧采集通过频率与启停验收：LO=80MHz，Fs=60MSPS，1024点 I 正弦、Q=0、32周期、峰值1500，2R2T。每路均有78.112/81.888MHz谱线，STOP 后消失。原始记录位于工程根目录 evidence/2026-09-30-dual-tx-scope。此结论不包含幅度校准、1Vpp保证、双端口幅度一致性或 HK-50 的80MHz器件校准。

## 目标及边界

先完成可在现有触摸屏操作的 AD9361 双 TX 验收正弦数据链：编辑参数→显式布防/初始化/配置→加载波形→确认发射→真实遥测显示正在发射→停止/解除。接入现有 RF 控制区，独立于原 ACM2108 AWG/数字调制控制；后续把任意波形和调制数据映射到 AD9361 是独立阶段。

保留用户已经批准的规则：仅成功的控制请求刷新30秒看门狗期限，只读轮询不续期。本阶段不新增自动续期、不重试启动、不自动重新布防。发射到期会停止，界面跟随硬件回读恢复；界面注明“30秒无控制操作后自动停机”。

## 方案比较

1. 推荐：复用 RF 状态客户端，在 TX 活跃期间保留同一连接，轮询和控制共用它。保持守护进程现有断线停机语义，不需要重建 PL 或新增 daemon 控制接口。
2. 改 daemon 为多客户端/独立控制租约：能改善外部观察并发，但扩大 C 服务与所有权协议变更范围，不作为首阶段。
3. 用启动脚本后台持有连接：适合仪器验收，缺少面板生命周期管理，容易再次出现已返回成功却断线停机的误显示。

## 数据与模型

RF 频率/采样率/衰减/带宽/2R2T/IDELAY 继续显式填写并确认。新增验收波形参数：1024点固定长度，I 正弦，Q=0，循环播放；用户显式填写周期数1..511、峰值1..2047。周期数与实际应用采样率决定基带频率，不以未应用的草稿推断实际输出。

tx.load 的 s16_iq_le 数据由 worker 生成，每点 int16 I/Q 交错，共4096字节。保持12位有符号峰值范围，避免截断。加载与启动独立；修改波形或 RF 草稿取消确认并使“已加载”准备状态失效，运行中禁止重新加载/改配置，STOP 随时可达。

新增模型动作 load/start，分别受 tx.load/tx.start 广告门禁限制。只有配置成功并加载成功才允许 start，start 需要第二次触摸确认。动作成功只是请求结果；“正在发射”必须由新鲜遥测中的 TX_ACTIVE、io_ok=true、source_selected=true 共同证明。断线、过期、看门狗停机、重连均清除运行显示和已加载准备状态；不会自动恢复发射。

## 连接及错误处理

未加载波形前，普通状态查询与布防/配置保持短连接。这些预备短连接的正常关闭不算发射连接故障。**从 tx.load 起保持连接**，加载后的回读、0.5秒轮询、后续 tx.start 及发射回读复用同一连接。STOP/解除在同一连接上执行，随后关闭并使加载准备状态失效；客户端/worker 退出也关闭，daemon 的既有断线处理停止 TX。该持有连接异常中断/重建、遥测变为未武装/过期均使已加载失效，必须重新确认加载，禁止自动重发 start。每个连接只握手一次，维护响应缓冲和递增 ID；二进制 payload 跟在 tx.load JSON 后，发送前检查元数据长度，拒绝时不探测未知能力。必须有 load→只读轮询→start 的原生协议回归。

持有连接在到期回读 armed=false（即使 state=OFFLINE 时连接仍存活）或遇到错误/未知状态后立即关闭，清除已加载状态，返回短连接只读轮询。READY 在已加载但尚未发射期间属于正常准备状态，不触发关闭；TX_ACTIVE→READY 表示发射已停止，关闭并清除已加载。显式 STOP 同样关闭。后续布防可建立新短连接，不得让客户端自己的旧连接占用单连接服务。测试覆盖到期→释放持有连接→显式重新 arm，但重新 arm 后仍不自动启动。

TX 活跃期间 daemon 同步服务单连接，其他外部原生客户端可能等待/超时；面板自己的状态轮询必须共用控制连接。不得并发建立第二个 RF 连接作为面板回读通道。保留 _io_lock 与 worker 出版序列锁，初始化和配置仍在后台，STOP 可排队且不阻塞触摸事件线程。保留真实 daemon 错误码，失败不自动重发 start。
