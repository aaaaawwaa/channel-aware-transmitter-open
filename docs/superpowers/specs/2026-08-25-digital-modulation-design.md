# FPGA 内部 BPSK/QPSK/QAM 发射链路可行性设计

日期: 2026-08-25
状态: 已批准（总体架构、映射/时序、验证边界和 GUI 方案 A 均已确认）
硬件基线: AC820（xc7z020clg484-2）+ ACM2108 双 DAC；Zynq-7020 PL 运行于 50MHz；现有链路为双通道 DDS、谐波合成、AM/FM/PM、相位联动和 PS ASCII 控制。

## 1. 目标与范围

暂时跳过任意波形，优先验证 FPGA 内部数字调制链路的可行性。第一阶段只实现并验证一个独立的 PL RTL 模块，不增加外部硬件、不增加 AXI 外设、不修改现有 `awg_top` 波形链路，也不接入 GUI 或串口协议。

目标模式:

- BPSK;
- QPSK;
- 4QAM（与 QPSK 使用相同四点映射，但保留独立模式名）;
- 16QAM;
- 64QAM。

`nQAM` 第一阶段采用标准方形 QAM，仅支持 4、16、64 阶；不实现 8QAM、32QAM 或任意整数阶数星座。BPSK 单独作为二进制相移键控模式，QPSK 与 4QAM 的数学等价关系在规格中明确保留。

数据源采用 FPGA 内部确定性 PRBS7/固定序列。第一阶段的可行性出口为 Python 参考模型与 RTL 仿真一致，不要求板级 I/Q 测量、内部解调或误码率闭环。

## 2. 总体架构

新增模块 `iq_digital_mod`，作为 Zynq PL 内部 RTL 资源，不是外接外设。模块逻辑最终由 Vivado 综合为 LUT、触发器和少量组合逻辑；第一阶段不要求 BRAM。

```text
50MHz PL 时钟
    │
    ├── PRBS7 固定序列发生器
    │
    ├── 按调制阶数提取 1/2/4/6 bit
    │
    ├── Gray 映射与幅度归一化
    │
    └── signed I/Q 8-bit 输出 + symbol_valid
```

第一阶段接口建议:

```verilog
module iq_digital_mod #(
    parameter integer SYM_TICKS = 5000
) (
    input  wire             clk,
    input  wire             rst_n,
    input  wire             enable,
    input  wire [2:0]       mode,
    output reg signed [7:0] i_sample,
    output reg signed [7:0] q_sample,
    output reg              symbol_valid
);
```

模式枚举在模块和 testbench 中统一定义:

```text
0 = BPSK
1 = QPSK
2 = QAM4
3 = QAM16
4 = QAM64
5..7 = 保留/非法
```

模块禁用时输出 `(0,0)`、清零符号计数并恢复 PRBS7 固定种子；重新使能后从相同首个符号开始。模式只在符号边界被采样，避免一个符号中途改变星座点。非法模式输出 `(0,0)`，仿真中报告错误。

后续集成阶段再把模块输出接到 `awg_top` 的模式选择器:

```text
iq_digital_mod.i_sample → DAC0(I)
iq_digital_mod.q_sample → DAC1(Q)
```

数字调制关闭时，现有 SINE/SQUARE/TRIANGLE/SAW/PULSE/NOISE、谐波、AM/FM/PM 和相位联动路径保持原样。

## 3. PRBS7 与符号时序

PRBS7 使用固定非零种子 `7'b1111111`。每次取 `prbs[6]` 作为当前数据位，然后推进:

```verilog
bit      = prbs[6];
prbs_n  = {prbs[5:0], prbs[6] ^ prbs[5]};
```

状态只在符号边界推进。该序列应具有 127 bit 最大长度周期。以 seed=`7'b1111111` 开始时，前 16 个串行输出 bit 固定为:

```text
1111111000000100
```

每个符号从当前 PRBS 状态连续提取所需数量的数据位:

- BPSK: 1 bit/symbol;
- QPSK/4QAM: 2 bit/symbol;
- 16QAM: 4 bit/symbol;
- 64QAM: 6 bit/symbol。

固定时序:

- PL 时钟: 50MHz;
- 符号率: 10kSym/s;
- `SYM_TICKS = 5000`;
- 每个 I/Q 点连续保持 5000 个时钟;
- `symbol_valid` 在新符号开始时拉高一个时钟。

复位或 `enable` 上升后，模块从固定 PRBS 种子开始。Python 黄金模型必须复现相同的首个符号、bit 消耗顺序和符号边界。

## 4. 星座映射与归一化

采用最大坐标归一化，保证所有输出落在 `[-127,+127]` 内。为避免整数缩放后越界，16QAM 与 64QAM 的最大坐标取 `±126`。

### 4.1 BPSK

```text
bit 0 → I=+127, Q=0
bit 1 → I=-127, Q=0
```

### 4.2 QPSK/4QAM

两种模式逐点完全相同:

```text
bits 00 → I=+127, Q=+127
bits 01 → I=+127, Q=-127
bits 11 → I=-127, Q=-127
bits 10 → I=-127, Q=+127
```

该排列沿星座环路为 Gray 顺序。

### 4.3 16QAM

I、Q 各取 2 bit，Gray 电平为:

```text
00 → +126
01 →  +42
11 →  -42
10 → -126
```

四个 I 电平与四个 Q 电平笛卡尔积形成 16 个星座点。

### 4.4 64QAM

I、Q 各取 3 bit，Gray 电平为:

```text
000 → +126
001 →  +90
011 →  +54
010 →  +18
110 →  -18
111 →  -54
101 →  -90
100 → -126
```

八个 I 电平与八个 Q 电平笛卡尔积形成 64 个星座点。

此方案按最大坐标归一化，不保证不同阶数的平均功率相同；这是第一阶段有意选择的取舍，优先保证无削顶和星座点清晰可见。后续集成时再增加统一数字幅度控制或平均功率归一化选项。

## 5. Python 参考模型与 RTL 验证

拟新增:

```text
src/rtl/iq_digital_mod.v
src/tb/iq_digital_mod_tb.v
host/siggen/digital_mod.py
host/tests/test_digital_mod.py
```

Python 模型与 RTL 必须共享以下行为:

1. PRBS7 初始状态、反馈多项式和输出 bit 顺序一致;
2. 每个模式的 bit 消耗数一致;
3. 每符号 5000 个时钟的保持长度一致;
4. 映射表和整数幅度值逐点一致;
5. enable/复位后的首个符号一致;
6. QPSK 与 QAM4 输出逐点完全一致。

RTL testbench 至少覆盖:

- PRBS7 状态不锁零且 127 bit 后回到相同状态;
- BPSK 出现两个 I 点，Q 恒为零;
- QPSK 与 QAM4 各出现四个点且逐点相同;
- 16QAM 出现完整 16 点;
- 64QAM 出现完整 64 点;
- 所有输出绝对值不超过 127;
- 每个符号恰好保持 5000 个时钟;
- `symbol_valid` 只在边界产生单周期脉冲;
- 非法模式输出零;
- 复位/禁用后重复运行得到相同序列。

Python 测试至少覆盖:

- 各阶数的完整星座集合;
- Gray 相邻映射关系;
- PRBS7 周期;
- I/Q 均值和幅度边界;
- 前 127 个 bit/符号与固定黄金向量;
- 符号保持长度;
- Python 与 RTL 导出的逐符号结果一致。

可行性验收标准:

- 星座点数为 `2/4/4/16/64`;
- 127 bit PRBS 周期成立;
- 前至少 127 个符号 Python 与 RTL 完全一致;
- I/Q 没有削顶;
- 每个符号保持长度误差为 0;
- 非法模式不影响现有链路（第一阶段通过独立模块隔离保证）。

### 6.1 GUI 布局约束（后续集成阶段）

采用已确认的方案 A，在不改变主窗口空间结构的前提下收纳数字调制功能:

```text
顶栏: 连接控件 + 功能页签(标准波形 / 数字调制)
左侧: 当前功能对应的调参面板
右上: 单一预览区(时域 / 星座 / 理论-实测对比)
右下: 日志信息
```

- 顶栏增加“标准波形 / 数字调制”功能页签，不把全部数字参数继续堆叠到现有 `ChannelPanel`。
- “标准波形”页签显示现有 CH1/CH2 控件，原有布局和操作语义保持不变。
- “数字调制”页签显示一个共享的紧凑 `DigitalModPanel`，不重复渲染两套通道参数；首期包含调制模式（BPSK/QPSK/4QAM/16QAM/64QAM）、数据源状态（固定 PRBS7）和符号率状态（10 kSym/s）。
- 右上仍只有一个预览区，通过小型视图切换控件选择:
  - **时域**：显示 I/Q 两路符号保持波形；
  - **星座**：显示 Python 仿真生成的 I/Q 点集；
  - **对比**：有采集数据时叠加理论与实测，没有采集数据时明确标注为仅仿真，不伪造硬件结果。
- 右下日志区保持现有位置和功能，用于显示模式切换、仿真状态和后续硬件采集状态。
- 当前串口协议不能直接返回 DAC 采样，因此“对比”模式的实测曲线必须等后续接入示波器/采集文件数据源后才启用；第一阶段只显示理论时域和星座结果。

## 7. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| PRBS bit 顺序与 Python 不一致 | 黄金序列无法对齐 | 在规格中固定 seed、取位和反馈，加入首个符号黄金向量 |
| QPSK 与 4QAM 被误实现为不同星座 | 兼容性和测试失败 | 两个模式复用同一映射函数，并做逐点相等测试 |
| 64QAM 整数缩放越界 | DAC 削顶 | 使用 `±18/±54/±90/±126`，testbench 检查范围 |
| 符号边界 off-by-one | 符号率错误 | `symbol_valid` 和 5000 周期计数单独测试 |
| 后续集成污染现有链路 | 原有功能回归 | 第一阶段模块隔离；集成时使用明确的数字模式 mux，OFF 路径保持原逻辑 |
| 平均功率随阶数变化 | 不同阶数幅度不可直接比较 | 第一阶段明确采用最大坐标归一化，后续再增加功率归一化选项 |
