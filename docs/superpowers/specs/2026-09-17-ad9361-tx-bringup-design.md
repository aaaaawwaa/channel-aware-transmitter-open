# AD9361 TX 上板打通设计（从 L1 控制面到"RF 口能观测到 TX 波形"）

- **日期**：2026-09-17
- **状态**：设计已逐节评审通过，待写实现计划
- **上游**：`docs/rf/migration_plan.md` 任务 1「独立 RF 基线」、`docs/rf/backend_contract.md`
- **已完成的起点**：L1 控制面 PASS（`docs/rf/boardtest.md`）—— `PRODUCT_ID` = 0x0A/rev2、

## 0. 背景：两个必须先说清的发现

### 0.1 我们自己的注释里有一处**自相矛盾**（采样率 ↔ DATA_CLK）

| 出处 | 说法 |
|---|---|
| `rf_overlay/rtl/phy_tx.v` | 1R1T 下用 **2 个 DATA_CLK 周期**发一个完整 I/Q 样点（6 根线 DDR = 每周期 12 bit，I/Q 各 12 bit 共 24 bit ⇒ 2 周期） |
| `rf_overlay/rtl/rf_tx_source.v` 的 `dds_ce` | 每 **2** 个周期推进一次 DDS，与上一致 |
| `rf_overlay/rtl/dds_inc.v` 的注释 | `f_out = phase_inc/2^12 × f_data_clk`，且"128 @ 30 MHz DATA_CLK → 937.5 kHz" ⇒ 隐含 `f_sample = f_data_clk` |

后两条**差 2 倍**。它的出处是 `docs/rf/example_project_notes.md` 里"LVDS DDR 下 60 MSPS 的
DATA_CLK 应是 30 MHz"——**那是笔记里的推测，不是实测**；例程自己的 XDC 又写了 25 MHz，笔记也已
标注存疑。

**处置：两者都不当前提。** 这正好变成更强的判据 —— 新增的 PL 状态寄存器量出 `f_DATA_CLK`，示波器
量出单音偏移 Δf，两者一比，**`fs` 与 DATA_CLK 的真实关系被测量钉死**，而不是被注释钉死。

### 0.2 没有"芯片内部音源"这条路（一条错误注释的纠正）

初始假设是"参考工程的 `DDS_PHASE_INC` 写的是 AD9361 自己的内部 DDS"。**核查后是错的**：

| 查了什么 | 结果 |
|---|---|
| `ad9361.c` / `ad9361.h` 里 `DDS` | **0 处命中**；寄存器 `0x3E0–0x3E5` 一次都没用；唯一的 NCO 是 `0x0A0` 的 TX/RX quad-cal NCO，属校准不属音源 |
| 参考工程的 `DDS_PHASE_INC` | `#define DDS_PHASE_INC AXI_CTRL_BASE+8` —— **他们自己在 PL 里的 AXI 寄存器**，与本工程 `axi_ctrl` 的 `slv_reg2` 同类 |
| `platform.c` 的 `dac_init(phy, DATA_SEL_DDS, 0)` | **被注释掉了**，且 ADI 那个 DDS 属 **AXI-DAC HDL core**（在 PL 里）；本工程**故意不用** ADI 那套 HDL（`AXI_ADC_NOT_PRESENT`、绕开 ADI-DMA 正是设计前提） |

**⇒ `rf_overlay/rtl/dds_inc.v:6` 那句 "the AD9361's own internal DDS" 是错的**，需改成"参考工程在他们
自己的 PL 里做的 DDS"。同一次重建里改掉。

**后果（改变了 B 层判据的写法）**：唯一不依赖 PL 数据面的信号只有 **LO 泄漏**。见 §5.2 与 §6.1。

## 3. 第 1 节 — 架构与所有权

| 层 | 唯一所有者 | 负责 |
|---|---|---|
| PL 配置寄存器 | **新增的板上 C 程序** | `axi_ctrl_0`(0x40000000)：`phy_mode=1`(1R1T)、`idelay_en=0x7f`、`idelay_tap=15`、`phase_inc`；`axi_gpio_ctrl`(0x41200000)：9 位模式引脚；`pl_spi_0`(0x40001000)：AD9361 控制面 |
| AD9361 寄存器 | **厂商 no-OS 驱动**（原样编入 C 程序） | BBPLL、采样率链、LO、ENSM、TX 衰减、全部校准 |
| RF 观测 | **DSOX1102A 接 TX SMA** | 频率 / 幅度判据（见 §6.3） |

**`spi_probe.py` 与 `ad9361_init.py` 降级为 L1 诊断工具，不再与 C 程序并发运行** —— 同一批寄存器不能
有两个写者。

**为什么走"板上编译厂商驱动"这条路**：厂商驱动的 platform 依赖面**只有 8 个函数**，且 `clk_*`
抽象自包含在 `util.c`（348 行）里 —— 无需移植整个 ADI HDL 平台层。

## 4. 第 2 节 — PL / BD 改动（只重建一次）

### (a) 新增一个**只读状态寄存器**

回答"AD9361 的 DATA_CLK 到底有没有到 FPGA 引脚上"。

芯片侧驱动能告诉我们 ENSM 状态与分频值，但**只有 PL 能证明时钟真在跳**。做法：

- DATA_CLK 域一个自由计数器，取其中一位（如 bit15）当慢方波，经 **2-FF 同步**进 FCLK0 ——
  软件轮询该位是否变化即知时钟在跑；数一段**已知 FCLK0 时间窗内的跳变数**即**量出 `f_DATA_CLK`**；
- 同寄存器附 `rst_source_ok` 电平位，以及一个**粘滞"曾经见到过时钟"位**。

**放扩展 `axi_ctrl_0`**（模块源码就在 `rf_overlay/rtl/`，是我们自己的），加一个只读 STATUS 寄存器；
**不新增 IP、不动地址图**、与 RF 其它配置寄存器在同一块。

### (b) 修 `create_bd.tcl` 里已被推翻的 FCLK1 注释

那句"userspace 必须设 `pynq.ps.Clocks.fclk1_mhz = 200`"是错的 —— 实测会把正确的 200 MHz 改坏成
**142.857 MHz**（跌破 IDELAYCTRL 的 200±10 MHz 规格）。BD 已经把 FCLK1 设对了，`Overlay()` 也不重置
分频器。注释要改成"**核对**、不要**设置**"。

### (c) 修 `dds_inc.v` 的错误注释

见 §0.2。改为"参考工程在他们自己的 PL 里做的 DDS"。

### (d) `phy_mode` 必须显式写，且**有独立判据**

`phy_mode` 来自 `axi_ctrl_0/phy_mode` → `ad9361_phy_0/phy_mode` 的**软件可写寄存器**
（`create_bd.tcl`），BD **默认 0 = 2R2T**，而 AD9361 将被配成 **1R1T**（例程写 `PHY_MODE=1`）。

两者不一致时**数据总线全是垃圾**，而现象是静默的。所以：C 程序必须显式写 `phy_mode=1`，并把它列成
**独立检查项**而不是埋在初始化里。

> 反过来这也是阶段二的便利：2R2T **不需要改 BD**，软件写 `phy_mode=0` 即可。

### (e) 明确**不改**的东西

`axi_interconnect` 仍是 `NUM_MI=3`（不新增 AXI 从机）；不引入 BRAM / DMA；`tx_mode_dds` 常量仍为 0；
`NUM_MI`/地址图不变。

## 5. 第 3 节 — 板上 C 程序

### 5.1 目录结构：`rf_overlay/sw/board_app/`

```
vendor/        ad9361.c/.h  ad9361_api.c/.h  ad9361_conv.c  util.c/.h  common.h  config.h
               ← 从参考 zip 原样复制，不改一个字节；附来源与逐文件 sha256，
                 使"原样"这件事本身可验证
platform_rf.c  我们的 platform 层（8 个函数）
rf_main.c      我们的 main
Makefile       板上原生 gcc（已实测 armv7l / gcc 9.3.0 / GNU Make 4.2.1）
```

### 5.2 8 个函数 → 我们的外设

| 函数 | 接到哪 |
|---|---|
| `spi_init(dev, pha, pol)` | mmap `pl_spi_0`@0x40001000，按选定 SCLK 写 DIV；**断言** pha=1 / pol=0（mode 1）与 PL master 一致 |
| `spi_write_then_read(spi, tx, n_tx, rx, n_rx)` | **核心**：驱动 CTRL/INSTR/TXD0/TXD1 → 轮询 STATUS.DONE → 收 RXD0/RXD1；附 **trace 钩子** |
| `spi_read(spi, buf, n)` | 简单单字节读，供驱动旧接口用 |
| `gpio_init(dev)` | mmap `axi_gpio_ctrl`@0x41200000 |
| `gpio_direction(pin, dir)` | 空操作（9 位全输出），但保留影子以便发现误用 |
| `gpio_set_value(pin, val)` | 对 9 位输出寄存器做 **read-modify-write**；引脚号 0..8 = `{txnrx, enable, resetb, sync, en_agc, ctl0..3}`，与 BD 位序一致 |
| `udelay` / `mdelay` | `clock_gettime(CLOCK_MONOTONIC)` **忙等**，**不用** nanosleep —— 驱动用它做短轮询，nanosleep 的粒度会让初始化变慢并可能让校准错过时间窗 |
| `msleep_interruptible` | nanosleep |

外加 `gpio_is_valid`（0..8 为真）。

### 5.3 校验做成**两遍**（本节要点）

- **第一遍 trace（常开）**：每次事务按 `W/R addr data…` 追加到日志。**零时序改变**。产出的是
  **一份完整、可 diff、可提交的"到底写了什么"记录** —— 它存在，正因为传输层是我们建的。
- **第二遍 audit（独立开关，初始化全部跑完之后才做）**：**不在每次写后面插一次回读** —— 那会把 SPI
  流量翻倍塞进校准状态机内部，而 VCO 校准恰恰是有时间窗的。改成事后对**一份预先圈定的地址清单**
  重读、与最后写入值比对，**逐地址的豁免/掩码策略在测量前写死**。输出三分类：
  **已证实 / 已声明豁免 / 无法解释的不符**。
- 纪律：audit **不自动修正、不因失败中止**。无法解释的不符就是它最有价值的输出。

### 5.4 顺带拿到的免费诊断

驱动自己的 API（例程笔记点名说值得搬）：`ad9361_get_trx_path_clks()` 六个频点、
`get_en_state_machine_mode()`、`get_tx_lo_freq()`、`get_tx_attenuation()`、`get_tx_sampling_freq()`。

### 5.5 参数（沿用已在本板跑通的例程）

参考时钟 40 MHz、FDD、**1R1T**、DCXO `{8, 5920}`、fs = 60 MSPS、TX/RX LO = **80 MHz**、
RF 带宽 30 MHz、`tx_attenuation_mdB = 10000`、RX 增益 30 dB Slow-AGC、
`tx_lo_powerdown_managed_enable = 1`、
rx_path_clock_frequencies `{1280M, 320M, 160M, 80M, 40M, 40M}`、
tx_path_clock_frequencies `{1280M, 160M, 160M, 80M, 40M, 40M}`。

**TX/RX FIR 走旁路**（例程是开的）—— 本轮要的是一条频率可预测的干净单音，FIR 会引入我们不打算在本轮
标定的额外幅度与群延迟。

**LO = 80 MHz 的理由**：DSOX1102A 只有 100 MHz 带宽，1 GHz 载波看不见；AD9361 的 LO 下限是 70 MHz，
80 MHz 是"仪器能看见"与"留足余量"的交点，且例程已在本板跑通。

### 5.6 一条必须写进"不证明什么"的话

用的是**厂商驱动**，所以一次 PASS 证明的是**我们的传输层**（PL SPI master + 模式引脚 GPIO +
LVDS TX 数据面 + PL DDS），**不证明**我们对 AD9361 寄存器语义的理解。

## 6. 第 4 节 — 上板顺序与判据

判据仍在测量之前写死。**分两个阶段**，每步有独立的通过与退出条件，任何一步不通过就停在那里查，
不往下走。

### 6.0 运行前置条件（缺一项不要开始）

| # | 条件 | 为什么 | 怎么确认 |
|---|------|--------|---------|
| 0.1 | 板上**当前装载的是 `rf_overlay.bit`**（不是 `awg_merged` / `ledbtn`） | C 程序 mmap 的是 RF overlay 的地址图；装载别的位流时那些地址要么未映射、要么是别的逻辑 | 读 `.hwh` 取地址后探活（`PRODUCT_ID`） |
| 0.2 | 先**停 `pynq-status` 守护进程**再装 overlay | 守护进程持有 PL，第二个 `Overlay()` 会把板子卡死（本项目有前科，且只读地址也不行 —— 抢的是 FPGA manager） | 进程归属确认；卡死的恢复是 JTAG `rst -system` + `con` |
| 0.3 | C 程序需 **root**（走 `/dev/mem`） | — | — |
| 0.4 | 阶段一 C 程序与 `spi_probe.py` / `ad9361_init.py` **互斥** | 同一批寄存器不能有两个写者（§3） | 不同时运行 |
| 0.5 | PL 位流与 `create_bd.tcl` 的**同一次构建**（比对产物时间戳） | R7：本工程有"BD 修订落后致 AXI 写入不生效"的前科 | 核对 `.bit` / `.hwh` 时间戳 |

### 6.1 阶段一 —— 1R1T（参考工程已验证的配置）

#### Step 0 — C 传输层先复现已经 PASS 的 Python 判据

新写的 `platform_rf.c`（SPI + 模式引脚 GPIO + udelay）**在任何厂商驱动代码被调用之前**，必须用一份
最小的 C 自检复现 `spi_probe.py` 已经通过的 L1-a/L1-b 判据：

| # | 判据 | 期望 |
|---|------|------|
| 0.1 | `PRODUCT_ID` bits[7:3] | `== 0x08`（本板实测字节 **0x0A** = rev2） |
| 0.2 | 模式引脚顺序 | `enable=1` **先于** `resetb` 释放；复位释放后**轮询**取 ID（自检窗口内 NACK） |
| 0.3 | `REG_CTRL`(0x3DF) bit0 回环 | 写 `0x01` 读回 bit0=1，写 `0x00` 读回 bit0=0 |

**为什么必须先做这一步**：后面所有失败都会有两个可能来源 ——「厂商驱动/寄存器序列」和「我们的 C
传输层」。Step 0 把后者单独证明掉，之后再出问题就只剩一个变量。判据是**逐字照抄**已经 PASS 的那三条。

#### Step 1 — 只写 PL 配置，并拿到**否定判据**

写 `axi_ctrl`：`phy_mode=1`（1R1T）、`idelay_en=0x7f`、`idelay_tap=15`、`phase_inc=128`。然后读 PL 状态寄存器。

> **否定判据（这一步的核心）**：此时 AD9361 的 BBPLL **还没编程**，`DATA_CLK` 不存在，所以
> `f_DATA_CLK` 必须读成**「没有时钟」**。
>
> 如果观测通道在无时钟时也报「时钟在跑」，那**它是坏的**，后面 Step 3 的读数一律不可信。

这是本项目的一贯纪律：**先证伪观测通道，再怀疑被测对象**（先例：Linux 关掉 GPIO 的 APER 时钟致
`DATA_RO` 恒读 0）。`phy_mode=1` 单列成判据的理由见 §4(d)。

#### Step 2 — `ad9361_init` + 参数

跑厂商 `ad9361_init(&ad9361_phy, &init_param)`，参数见 §5.5。

| # | 判据 | 期望 | FAIL 的含义 |
|---|------|------|------------|
| 2.1 | `ad9361_init` 返回 | `0` | 有非零返回码，驱动自己报的错比我们的判据可信 |
| 2.2 | ENSM 状态回读 | `RX`/`FDD` 态（非 `SLEEP`/`ALERT`） | 拒绝进入使能态 |
| 2.3 | TX LO 回读 | ≈ 80 MHz（容差按 `MAX_SYNTH_FREF` 公式算） | — |
| 2.4 | TX 衰减回读 | 与写入值一致 | — |
| 2.5 | `ad9361_get_trx_path_clks` 六个频率自洽 | 与写入的 `tx_path_clock_frequencies` 一致 | 分频链没生效 |

> **2.3 的诚实边界**：LO 回读是驱动**按寄存器算出**的，不是测量值。它证明的是**寄存器自洽**，
> **不是 PLL 锁定**。真正的锁定证明只能在 Step 4 由示波器给出。写明这一点，免得把「算出来的数」
> 当成「测出来的数」。

#### Step 3 — PL 状态转正，并把 `fs ↔ DATA_CLK` 关系**测出来**

`DATA_CLK` 这时才出现。`f_DATA_CLK` 从「没有时钟」变成具体值 ⇒ **同一观测通道的正反两向都验过**
（Step 1 否定、Step 3 肯定）。

§0.1 的两处矛盾**不猜 —— 用 Step 4 的示波器测量裁定**。

#### Step 4 — 示波器判据

TX 输出经同轴电缆直连 CH1（有线，无天线）。**80 MHz 载波上示波器 100 MHz 前端的响应是未知的，
判决一律用「相对量」**，绝对幅度不作判据。

**B 层 —— 诊断判据（只判频率，不判幅度）**

| # | 判据 | 期望 |
|---|------|------|
| B1 | LO 频率处能分辨出一条线（LO 泄漏） | 位置在 80 MHz |
| B2 | LO 80 → 85 MHz，该线随之平移 | 平移量与设定一致 |

> **B 层只有频率判据，没有幅度阈值。** 能在 LO 处分辨出线、且它随 LO 平移 ⇒ B 层成立。
> 分辨不出 ⇒ 标注「**仪器受限，本诊断不可用**」，**不算失败**。
>
> 理由：B 层唯一的信号源是 LO 泄漏（§0.2 —— 没有芯片内部音源），幅度未实测，写不出有依据的阈值；
> 用看不清的弱信号当硬判据，就是这个工程反复吃亏的"判据缺陷被误读成 RTL 故障"。
>
> **B 层的价值是二分定位**：C 层失败时，B 层通 ⇒ 器件模拟链路是活的、问题在数据面；
> B 层也不可用 ⇒ 无法进一步分割。B 层**不是**独立的通过条件，**主判据是 C1/C2/C3**。

**提高 B 层可见性的两招（测量前先做）**
1. 用 `ad9361_set_tx_attenuation` 把 TX atten 置 **`0` mdB**（不是 10000 —— 白送 10 dB）。
   C3 再恢复按 §6.1 的 10000→30000 做。
2. 用 **FFT**，且**短时基保证采样率 ≥500 MSa/s**（62500 点 ⇒ ~62 µs 窗、16 kHz 分辨率，
   分辨 470 kHz 绰绰有余）。用 2 ms/div 会把采样率压到几 MSa/s，80 MHz 直接没影。

**C 层 —— 主判据**

| # | 判据 | 期望 | 为什么这么判 |
|---|------|------|------------|
| 4.1 | **谱线存在性** | LO 处一条（LO 泄漏）+ 关于 LO 对称的两条（`80±Δf`） | 载波与边带同时出现 = TX 链活着的直接证据 |
| 4.2 | **`Δf` 线性于 `phase_inc`** | `phase_inc` 128→256 时 `Δf₂/Δf₁ = 2.00 ± 2%` | 证明看到的是 DDS 音，不是杂散 |
| 4.3 | **`fs ↔ DATA_CLK` 关系被裁定** | `Δf` 落在两个候选之一；记录**是哪一个** | 不预设，只测量（见 §0.1 / Step 3） |
| 4.4 | **LO 平移** | LO 80 → 85 MHz，**所有**谱线整体平移 +5 MHz（含 LO 泄漏） | 证明这些线确实是被 LO 搬移的基带 |
| 4.5 | **衰减差值** | atten 10000 → 30000 mdB，信号线幅度**差值 ≈ 20 ± 3 dB** | 取**差值**消掉示波器前端频响 |
| 4.6 | LO 泄漏是否随衰减同步变化 | **只记录，不判** | 它说明衰减器相对泄漏路径的位置 |

#### Step 5 — 回读审计（第二次 SPI 遍历）

见 §5.3。与那条**始终开启的 trace** 是两件事，分两趟做。

### 6.2 阶段二 —— 2R2T（让 TX2 可判）

**前置事实：在 1R1T 下 TX2 通道是关闭的，CH2 上预期什么都看不到。** 而"看不到"与"通道坏了"长得
一模一样 ⇒ **当前配置下 CH2 有无信号都不构成判据**。要让 TX2 有判断力，AD9361 必须进 2R2T。

四个要点：

1. **不用改 BD。** `phy_mode` 是软件寄存器（§4(d)），软件写 `0` 即 2R2T。

   > **⚠ 2026-09-18 更正（原文保留，未改）**：这一条**只对了一半**，执行时按"完全不用改"做会
   > 让 TX1 的音频率翻倍。**寄存器不用新增，但既有连线要补一条**：`phy_mode` 原本只接到
   > `ad9361_phy_0`，而本设计第 3 条要求 `dds_ce` 周期也跟随 `phy_mode`，所以
   > `axi_ctrl_0/phy_mode` **必须同时接到 `rf_tx_source_0/phy_mode`**（`create_bd.tcl`）。
   > 也就是说阶段二**要改 BD 并重建一次**——这正是第 3/4 条已经在要求的"
   > 一次第二次重建"，本节开头那句"不用改 BD"与之矛盾，**以第 3/4 条为准**。
   > 另：`phy_mode` 是**非同步**跨时钟域信号（FCLK0 → DATA_CLK），写入纪律见
   > `rf_overlay/tools/impl1_clock_groups.tcl:12-14` 与 `docs/rf/boardtest.md` §9.3——
   > 是**次序**（DATA_CLK 尚未出现时写），不是"数据静默"，`phase_inc = 0` **不够**。

   > **⚠ 2026-09-18 更正之二（原文保留，未改）**：`plcfg` **不能**用来**询问** PL 当前是什么
   > 模式 —— 它的第一件事就是 `rf_reg_write(RF_REG_PHY_MODE, 1)`（`rf_main.c:585`），只能
   > **设定**。要读回真值必须用只读子命令 `plstate`（本轮新增）。第一次跑阶段二时因为用了
   > `plcfg`，一块故意留在 2R2T 的板子被写回了 1R1T，整套测量端到端跑的是 1R1T、数字与阶段一
   > 一模一样、全绿 —— **在什么都没测的状态下交了差**（计划缺陷 E28）。
2. init 参数 `two_rx_two_tx_mode_enable = 1`。
3. **⚠ 容易漏的坑**：`rf_tx_source.v:58-68` 的 `dds_ce` 走 `strobe_cnt` 的 **2 拍**周期，是按 1R1T 的
   "2 拍/样点"配的；`phy_tx.v:68` 显示 2R2T 是 **4 拍/样点**（`tx_data_cnt_reg == 'd3`）。
   **不改 `dds_ce` 周期，TX1 的音会频率翻倍** —— 症状是"C 层判据突然差 2 倍"，极易被当成器件问题。
4. **TX2 的载波判据零 RTL 改动**：数据全零时 TX2 只出 LO 泄漏，而 `rf_tx_source.v:89-90` 现在
   **本来就是硬置零** —— 正好是所需状态。所以阶段二的 **B 层搬到 CH2 不用改 RTL**。
   要测 TX2 的**音**才需要给 `d2/q2` 喂数据 —— 这次 RTL 改动**顺带把第 3 条的 `dds_ce` 周期一起改**，
   用**一次**第二次重建做完；否则重建两次、且中间那次 TX1 的音频率是错的。

### 6.3 测量装置要求

| 项 | 要求 |
|---|---|
| 连接 | TX SMA → 同轴电缆 → 50 Ω 馈通端接 → 示波器 CH1（CH2 同于阶段二） |
| 时基 / 采样率 | 短时基，保证 ≥500 MSa/s；62500 点记录长度 |
| `:WAV:POIN` | **不要写** —— 它把记录长度钉成手动值且 `:MODE NORM` 复位不了，会让所有基于波形捕获的用例成片误判 |
| 判决量 | 一律**相对量**（差值、比值、位置），不用绝对幅度 |

## 7. 本设计**不**证明什么

| 不证明 | 为什么 |
|--------|--------|
| **RX 数据面可用** | `ad9361_phy` 的 RX 输出在 BD 里悬空，RF overlay 里没有 BRAM、没有 DMA。本轮明确只做 TX |
| **我们的寄存器语义理解正确** | 用的是厂商驱动。一次 PASS 证明的是**我们的传输层**（PL SPI master + 模式引脚 + LVDS TX 数据面 + PL DDS），**不证明**我们对 AD9361 寄存器语义的理解 |
| **I/Q 顺序与镜像抑制** | **NOT RUN**。理由：当前 DDS 是 I-only（`dac_data_q1` 恒 0），输出是**双边带**，没有"哪一侧"可看；且无 RX 通路做接收验证。见 §8 |
| **RF 性能指标** | 不测 EVM、不测镜像抑制的 dB 数、无校准后指标 |
| **射频合规 / 功率** | 有线连接，无天线，不涉辐射 |
| **长期 / 温度稳定性** | 单次测量 |
| **TX2 在 1R1T 下任何结论** | 该模式下 TX2 本就关闭，沉默不构成证据（§6.2） |

## 8. 已定的子决策与相对初版的修订

| # | 初版 | 定稿 | 理由 |
|---|------|------|------|
| 1 | LO 定 1 GHz | **LO = 80 MHz** | DSOX1102A 仅 100 MHz 带宽，1 GHz 载波看不见；80 MHz 是 AD9361 下限 70 MHz 之上、仪器可见、且例程已在本板跑通的交点 |
| 2 | 用外部 SDR 观测 | **用 DSOX1102A + 下调频率** | 用户决定 |
| 3 | 实现路线未定 | **板上编译厂商 no-OS 驱动，只写自己的 platform 层** | 用户决定；依赖面仅 8 个函数 |
| 4 | 范围含 RX | **只做 TX** | 用户决定；RX 输出在 BD 里悬空，是真正的数据面工程 |
| 5 | 任务定位 = `migration_plan` 任务 1 完整通过条件 | **"AD9361 能不能用"**，暂不与项目逻辑结合 | 用户明确；使 I/Q 判据不阻塞本轮 |
| 6 | B 层 = "最硬证据" | **B 层降级为诊断判据（只判频率）** | §0.2 —— 无芯片内部音源，唯一信号是 LO 泄漏，幅度未实测写不出阈值 |
| 7 | 单边 DDS 需改正交（推荐） | **本轮 NOT RUN，保持 I-only** | 用户定位为独立器件验证；I/Q 顺序属任务 1 完整通过条件，留到与项目逻辑结合、且有 RX 通路那一轮 |
| 8 | 一次测两个通道 | **两阶段：先 1R1T 打通 TX1，再 2R2T 测 TX2** | 用户决定；2R2T 组帧未经参考工程验证，先有 TX1 基线才能分辨"2R2T 组帧错"与"TX2 通道坏" |
| 9 | TX atten 固定 10000 mdB | **B 层观测前置 0 mdB**，C3 再按 10000→30000 做差值 | 提高 LO 泄漏可见性 |

### 仍未决（不阻塞本轮）

## 9. 风险与未决项

| # | 风险 | 缓解 |
|---|------|------|
| R1 | **`fs ↔ DATA_CLK` 关系未定**（§0.1 两处注释矛盾） | 判据 4.3 把它**测量**出来而不是假设；Step 1 的否定判据保证测量通道先可信 |
