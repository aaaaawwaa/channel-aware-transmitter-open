- **日期**：2026-09-19
- **状态**：**计划，未执行**
- **目标**：把 `docs/rf/usability_assessment.md` §3.3 的 D1–D5 从"未做"推进到"已实测"
- **项目定位（本方案的取舍依据，2026-09-19 用户明确）**：最终形态是**"按照接收信号的信道环境

  外部设计文档的适用性评估见 `docs/rf/channel_ai_assessment.md`。

## 0. 本轮的边界（先写清楚不做什么）

「补样点通路」与「把 AWG 链迁过来」**是两件事**，本计划只做前者。

| 事 | 本轮 | 为什么 |
|---|---|---|
| PS→PL→AD9361 样点通路（BRAM + 播放器） | **做** | 就是 D1–D5 |
| AWG 链（PRBS7/RRC/QAM…）迁进来 | **不做** | 属 M1/M2 迁移，`migration_plan.md` §4 Task 3 |
| **5/6 分数比速率转换** | **不做** | 见 §1.6：**本轮的架构里它没有位置** |
| **RX 采集（AD9361→PL→PS）** | **做**（2026-09-19 用户裁决加进本轮） | **当测量仪器用，不当交付物**——见 §9。它把 D1/D2/D4 从"看频谱变了"升级到逐位比对，并关闭 M4 |
| 连续流式（非周期播放）驻留 | 不做 | §3.3 明确不要求；且 GP0 带宽不够（§1.6） |
| 多文件无缝切换 | 不做 | §3.3 明确不要求；R3 明写这是两件事 |
| 闭环 BER | 不做 | §3.3 明确不要求 |

**本轮不做速率转换，不是省钱，是它在本轮架构里根本不存在** —— 论证见 §1.6。
迁移阶段要付这笔账，届时再付（§7）。

## 1. 设计

### 1.1 架构

```
PS 用户态 (mmap /dev/mem, board_app)
  │  AXI-Lite 写  M_AXI_GP0 @ FCLK0 = 50 MHz
  ▼
axi_bram_ctrl_1 ──PORTA──► blk_mem_gen_1  (True Dual Port, 32-bit, 4 K words)
                                    │ PORTB  (DATA_CLK 域)
                                    ▼
                    rf_tx_source 内的样点读取器   ← 复用已有的 dds_ce 样点节拍
                                    │ ext_dac_valid / d1 / q1 / d2 / q2
                                    ▼
                              rf_tx_source (mode = 1)
                                    ▼
                                 phy_tx ──► AD9361
```

**关键点：双口 BRAM 本身就是速率解耦器。** A 口由 PS 以任意速率写，B 口由 DATA_CLK
域的读取器读。**速率的"主"是读取器**，因此"PS 写 → PL 按 60 MSPS 播"这条通路里
**不存在需要转换的速率比**。

### 1.2 BD 改动（`rf_overlay/bd/create_bd.tcl`）

照 `scripts/create_bd.tcl:99-131`（AWG 侧已验证的范式）搬，**逐条复刻已付过代价的参数**：

| 项 | 值 | 为什么 |
|---|---|---|
| `axi_bram_ctrl` | `DATA_WIDTH {32}`、`SINGLE_PORT_BRAM {1}` | `SINGLE_PORT_BRAM=1` 才让 PORT B 留给 PL |
| `blk_mem_gen` | `Memory_Type {True_Dual_Port_RAM}`、宽 32/32、深 4096、`Enable_A/B {Use_ENA/ENB_Pin}`、`Use_Byte_Write_Enable {true}`、`Byte_Size {8}`、**`Enable_32bit_Address {true}`** | **最后一条是根因级陷阱**：BD 把地址口固定成 32 位（BYTE_ADDRESS），该参数为 false 时 generic 自相矛盾（`C_ADDRA_WIDTH=32` 但 `C_ENABLE_32BIT_ADDRESS=0`）→ **静默综合成 0 个 RAMB 的空网表**（AXI 照常握手、读恒 0、不报错） |
| PORT B | `clkb` ← `ad9361_phy_0/data_clk`；`dinb`/`web` ← `xlconstant` 0 | 时钟**直接由 BD 接**，不穿模块端口（AWG 侧 `bram_b_clk` 那套穿端口写法是历史包袱） |
| `dinb` 常量宽度 | 32 | 位宽必须精确匹配；AWG 侧注释记过"1 位常量接 12 位口只连 LSB 且其余悬空"的静默错误 |
| `web` 常量宽度 | **4**（不是 1） | `Byte_Size=8` + 32 位口 ⇒ 4 位字节使能 |
| 地址段 | `assign_bd_address` 后把该 BRAM 段 `RANGE` 设 4K | AXI BRAM Ctrl 的最小孔径是 4K |
| `axi_interconnect_0` | `NUM_MI {3}` → `{4}` | 并加 `M03_AXI` 接口连接 |
| 时钟/复位循环 | `:212` 的 `foreach` 加 `M03_ACLK`；`:241` 的 `foreach` 加 `M03_ARESETN`；新从机的 `s_axi_aclk`/`s_axi_aresetn` **按显式引脚名**接 | 本项目已记：`*_aclk` 通配在 `pl_spi_master` 这种手写模块上静默匹配不到 |
| 删掉 | `tx_mode_dds` 常量（`:193-195`）、`tx_ext_zero_v`/`tx_ext_zero_d`（`:109-113`） | `mode` 与 `ext_dac_*` 改由真实逻辑驱动 —— 这正是 D1 的字面要求 |

**⚠ 地址会移动**：`platform_rf.h:10-11` 自己写着"addresses move when the BD changes，
re-read the .hwh after every rebuild"。新增从机后必须**从 `out/rf_overlay.hwh` 重读
三个基址**，不许照抄 `0x40000000`/`0x40001000`/`0x41200000`。

### 1.3 RTL 改动

**新增 `rf_overlay/rtl/rf_sample_reader.v`** —— 独立模块，由 `rf_tx_source` 实例化
（**不写成内联子块**：独立模块才能在 TB 里单独喂 `ce` 验证节拍，与 AWG 侧把读取器
写成独立模块 `user_bit_source` 是同一决定）。

- **复用已有的 `dds_ce`** 作样点节拍（`rf_tx_source.v:96-108` 算出，1R1T 周期 2、2R2T 周期 4）。
  **这是本设计最重要的一条**：读取器与 DDS **共用同一个样点边界**，因此
  「1R1T 下 2 拍/样点、2R2T 下 4 拍/样点」这个关系**不可能在两条路之间分叉**。
  本项目正因这类分叉吃过亏（`spec §6.2:322-324`：「不改 `dds_ce` 周期，TX1 的音会频率翻倍」
  —— 症状会被读成"器件在新模式下行为不同"）。
- B 口地址按 **`word << 2`** 给**字节地址**（`Enable_32bit_Address=true` 的连带规则，
  AWG 侧 `awg_top.v:495` 同一写法）。
- 读延迟处理：BRAM 同步读 1 拍。`dds_ce` 周期 ≥2 拍，故「`dds_ce` 时呈现已寄存的数据 +
  发下一个地址，次拍寄存 `bram_rdata`」在 1R1T 下恰好有 1 拍余量，2R2T 下更宽。**不引入 FIFO。**
- 新增端口：`bram_en`、`bram_addr[31:0]`、`bram_rdata[31:0]`；配置 `src_sel`、`smp_len[12:0]`、
  `smp_loop`、`smp_commit`；状态 `smp_pos[12:0]`、`smp_word[31:0]`。
- **跨域纪律**：`src_sel`/`smp_len`/`smp_loop` 从 FCLK0 进 DATA_CLK 域。
  单比特（`src_sel`/`smp_loop`）走 2-FF，与 `wave_sel_sync`（`:60-67`）同型。
  **多比特 `smp_len` 不用 2-FF 直接过**——位间偏斜会让长度错一个样点。
  改用**提交 epoch**：软件翻转 `smp_commit`，DATA_CLK 侧对翻转沿做 2-FF 同步后**整字加载**。
  这是本项目已跑通的范式（`chan_cfg` 的 commit epoch），不新发明纪律。

**`rf_overlay/bd/create_bd.tcl` 的连接**：`mode` 由常量改接 `axi_ctrl_0/src_sel`；
`ext_dac_*` 接读取器输出。

### 1.4 寄存器分配（`axi_ctrl`，16 槽 `0x00..0x3C`，现只用了 0–4、10）

| 偏移 | 槽 | 方向 | 字段 |
|---|---|---|---|
| `0x14` | reg5 | RW | `[0] src_sel`（0=DDS，1=BRAM）、`[1] smp_loop`、`[2] smp_commit`（软翻转发提交） |
| `0x18` | reg6 | RW | `smp_len[12:0]`（1..4096） |
| `0x1C` | reg7 | RO | `smp_pos[12:0]`（当前读指针，回读用） |
| `0x20` | reg8 | RO | `smp_word[31:0]`（最近从 BRAM 读出的那个字） |
| `0x28` | reg10 | — | 已占用（`wave_sel`） |

`reg8` 回读"最近读出的字"是给 D1 做**自洽性交叉检查**用的：软件知道自己写了什么，
读到的必须是它写的那一个（或相邻的），否则地址换算（`word << 2`）就错了。
**但它不能单独作为 D1 的证据**——它证明不了数据到了 RF 口。真正的证据在示波器上（§2）。

### 1.5 样点字格式

32 位一个字，一个 I/Q 样点：**`[15:0] = I`、`[31:16] = Q`**（二进制补码，各只用低 12 位）。

选 16 位字段而非 12 位紧排，是为了让软件侧就是两个 `int16`（C 与 Python 都平凡），
而硬件侧切片不变（`w[11:0]` / `w[27:16]`）。**深度 4096 字 = 16 KiB**。

### 1.6 为什么本轮不需要速率转换器

`usability_assessment.md` §4.1 的 **M2**（"速率不匹配 50 MSample/s vs 60 MSPS"）描述的是
**AWG 链输出样点**与 RF 采样率之比。本轮的数据源是**PS 写进 BRAM 的静态缓冲**，不是
50 MHz 时钟上的活样点流。**BRAM 的 B 口由谁读、读多快，与 A 口被谁、以什么速率写无关。**
所以：**速率的"主"是 DATA_CLK 域的读取器，比例恒为 1。**

`migration_plan.md:125-126`「不能靠异步 FIFO 解决长期速率不匹配」说的是**活流**的情形，
与本轮的缓冲播放不冲突，本轮也不使用异步 FIFO。

**反过来，有一条本轮必须如实记下的上限**：PS 经 `M_AXI_GP0`（32 位 @50 MHz）写样点的
可持续吞吐**远低于** 60 MSPS × 4 B = **240 MB/s**，所以**连续流式驻留不可能走这条路**
（`S_AXI_HP0` 在本 overlay 是 disabled，`ps7_props_rf.tcl:16-20`）。
本轮要的是**有限缓冲的周期播放**，与 D2「至少 64 点」的字面要求一致。
**连续流式留给迁移阶段，届时那条路必须开 HP0/DMA** —— 记在 §7，不在本轮。

### 1.7 顺带修一处已定位的约束缺陷：`data_clk` 周期

**这不是本轮的新发现，但本轮必须修它，因为它决定本轮的全部时序证据是否成立。**

`rf_overlay/constraints/rf.xdc:89-99` 写的是：

```tcl
# At 60 MSPS in DDR mode DATA_CLK is 30 MHz, so the period is 33.333 ns.
create_clock -name data_clk -period 33.333 [get_ports rx_clk_in_p]
```

**真值是 120 MHz（8.333 ns），差了 4 倍。** 四条独立证据：

1. **结构性（最硬）**：`phy_tx` 用 6 条 lane × DDR = **每个 DATA_CLK 周期送 12 位**
   （`phy_tx.v:105-114`：`cnt=1` 送 `[5:0]`、`cnt=0` 送 `[11:6]`）。一个样点是
   12 位 I + 12 位 Q = **24 位 ⇒ 恰好 2 个周期**，故 `DATA_CLK = 2·fs`。
   而 30 MHz = `fs/2` 意味着**半个时钟周期送一个 24 位样点** —— 物理上不可能。
2. **实测的 DDS 边带间距**（对真实输出的直接测量）：`phase_inc=128` 时实测 `Δf = 1872.0 kHz`，
   而 `Δf = phase_inc/2^12 × (DATA_CLK/2)` ⇒ `DATA_CLK/2 = 60 MHz` ⇒ **120 MHz**（差 0.16%）。
   见 `l2_stage1_record.md:186-192`。
3. **折回算术**：`win_cycles = 13107`，`13107 + 65536 = 78643 = 120.0 MHz × 655.36 µs`，逐位相符
   （`boardtest.md:320-327`）。
4. **阶段二**：报 `40.001 MHz` ⇒ `+65536×3 = 240 MHz`，正是 2R2T 的 `4·fs`（`boardtest.md:705`）。

**2026-09-19 上板实测——第 5、6 条，都是板上直接读出来的：**

5. **AD9361 自己的时钟链回读**（`ad9361_get_trx_path_clks`，在 `set_sampling_freq` **重算之后**读的，
   所以是实际编程值，不是 SDD R19 说的那组"重算前"值）：

   ```
   TX path clocks: 960M  240M  120M  120M  120M  60M
                                 ^^^^  ^^^^^^^^
                                 CLKTF  TX_SAMPL
   ```

   **CLKTF = 120 MHz**，`TX_SAMPL = 60 MHz`。**120 = 2 × 60** ✓

6. **示波器独立测量（T01 判据，`RESULT PASS`）** ——
   用 `rf_overlay/sw/scope_data_clk_probe.py`，判据**测量前写死**：

   | | |
   |---|---|
   | 方法 | `Δf = (f_上边带 − f_下边带)/2`，**取差值以消掉 LO 误差** |
   | 候选 | 120 MHz → **1875.0 kHz**；20 MHz → 312.5 kHz（**相差 6 倍，不可能认错**） |
   | 实测 | 78.1120 / 81.8880 MHz，中点 **80.0000 MHz** ⇒ `Δf = 1888.0 kHz` |
   | 重复性 | 3 次捕获散布 **0.0000 kHz** |
   | 判定 | 只匹配 **120 MHz** |

   （1888.0 kHz vs 预测 1875.0 差 0.69%，在 2 GSa/s / 62500 点的 **32 kHz bin** 内——
   1875 kHz 落在 58.59 号 bin，取整到 59 号 = 1888 kHz。**分辨率内符合。**）

   **NV 已内建**：`phase_inc=0` 时必须无边带（未跑，记为待做）。
   **另**：该脚本自检曾抓到一条**无效断言**（喂进去的是精确等于候选值的数，
   任何容差都会匹配），已改为"1875.1 kHz 在 1e-6 容差下必须被拒"。

**⇒ 六条证据，两条是板上实测，全部指向 120 MHz。判据成立。**

**处置**：约束改为**从单一常量按最坏情况推导**，不再手填：

```tcl
# DATA_CLK = 2 x sample rate in 1R1T, 4 x in 2R2T (phy_tx puts a 24-bit I/Q
# sample out over 6 DDR lanes at 12 bits per DATA_CLK cycle).  The overlay
# switches framing AT RUN TIME and one static constraint can only declare one
# period, so it declares the WORSE one.
#
# A constraint looser than reality is worse than useless: it reports MET for
# paths that would fail.  The previous value here (33.333 ns) came from a
# comment claiming DATA_CLK was 30 MHz and survived several builds uncaught.
set RF_SAMPLE_RATE_HZ 60000000
create_clock -name data_clk -period [expr {1e9 / (4 * $RF_SAMPLE_RATE_HZ)}] [get_ports rx_clk_in_p]
```

**已用量测确认它不会立刻炸**（只读探针，打开现有已路由 DCP，与约束无关地读数据路径延时）：

| 项 | 实测 |
|---|---|
| 时钟 | `clk_fpga_0` 20 ns、`clk_fpga_1` 5 ns、`data_clk` 33.333 ns |
| WNS 11.717 ns 的归属 | **`clk_fpga_0`**（延时 7.428 ns / 20 ns），**不是数据域** |
| `data_clk` 域内最差**建立**路径 | **2.888 ns**（logic 0.379 + route 2.509） |
| ⇒ 真实 8.333 ns 下的余量 | **≈ +5.3 ns** |
| ⇒ 2R2T 的 4.167 ns 下 | **≈ +1.1 ns**（仍为正） |
| `data_clk` 域内最差**保持**路径 | 0.066 ns（保持与周期无关，**不是**本缺陷造成的，是原有薄余量） |

所以这条修复是**把一个诚实的数字换上去**，不是制造一个新失败。若重建后 240 MHz 不收敛，
那是**真信息**，按本项目纪律不许放宽周期去让它变绿。

## 2. 判据（**测量前写死**，测完不回头改）

D1–D5 是上游写死的完成定义，下面是它们的可执行形式。**每条配 `PASS NV` 负例。**

### 2.1 判据本体

| # | 对应 | 判据 | 证伪 / NV |
|---|---|---|---|
| **C1** | D1 | `src_sel=0`（DDS）与 `src_sel=1`（BRAM）在同一 LO、同一衰减下，**谱线必须不同** | **NV**：`src_sel=1` 但缓冲装**全零** ⇒ 输出必须塌到**无谱线**（不是"变成另一个音"） |
| **C2** | D2 | 存 N 点**复数**正弦 `I=cos(2πk/N)`、`Q=sin(2πk/N)` ⇒ 输出是**单边带** `LO + 60e6/N` | **NV**：换 N（64→128→256）⇒ 频率**必须**按 `60e6/N` 变；不变即 `ext_dac_*` 仍是死的 |
| **C3** | D3 | 实测 `Δf` 与 `60e6/N` 比较，容差 **±3%**（沿用本项目相对判据的容差尺度） | **R7**：同板无外部绝对参考，**只验相对频率**（`Δf`），**不认证 LO 绝对精度**。这条写进结论 |
| **C4** | D4 | **Q 活着 ⇒ 单边带**：`Q=sin` 时 `LO−f` 必须**读不出来** | **NV**：`Q=0`（实数正弦）时**必须**出**双边带** `LO ± f`。**单/双边带是符号明确的一比特判据**，不可能误读成"测量余量" |
| **C5** | D5 | 上述每条 NV 都要实跑并如实报 | 任一条 NV 不成立 ⇒ 对应判据作废，不许只报正面 |
| **C6** | D1/D2 | **片内回环比对**：写已知 I/Q 图案 → 开回环 → 读回 → 与写入序列比较。**判据分两种结果**，见 §2.3：完全逐位相同 ⇒ 回环在数字滤波器**上游**；一致地被滤波 ⇒ 在下游。**两种都算 PASS，但结论不同，必须写明是哪一种** | **NV1**：改一个样点，回环必须跟着变；**NV2**：回环关时必须**对不上**。**实测（2026-09-19，四轮修正后）：回环是双稳态的 —— 好态逐位精确（整数延迟 + I/Q 交叉）；坏态现在**也有模型**：`{前一样点的高 6 位, 本样点的低 6 位}`（I/Q 交叉保留），是**双射**、逐位可恢复，C12/C13/C16 已在坏态判过（§2.4.1）。开关未知，但 `init` 会重掷它。⇒ **"逐位"两态都成立**；NV2 原记 FAIL **已撤销**（负控从未真正清零，是测试台缺陷），修正后的负控已跑且通过**，见 §2.3.1 / §2.4.1 |

| **C8** | 仪器边界 | **数字/模拟判别**（§6.5.4）：回环开着，`tx_attenuation` 变，记回环幅度**动没动** | 这条**不是通过/失败判据，是定性判据**。**实测（2026-09-19）：0 / 10000 / 30000 mdB 三档捕获逐点相同 ⇒ 回环点在模拟衰减器上游，是数字回环** |

### 2.1.1 为什么单列 C17（用户 2026-09-19 定的方向）

**方向**：**弃用 ACM2108，全面迁移到 AD9361。**

**这条方向把 C17 从"顺手检查"变成"架构验证"**：迁移完成后，**板上 Python 直连就是主路径**，
`board_app` 那条 SPI 路退化为配置工具。所以"PYNQ 能不能直接读写信道缓冲"不再是锦上添花，
**而是 T05（端侧观察/建议/受控发射）的地基**——如果这条路走不通，T05 的架构要改。

**同时它也是本轮改动的一个副产品**：改动前 RF overlay 里**一个可寻址存储器都没有**，
所有控制必须走 SPI、由 `board_app` 逐条发送。新增的两个 AXI BRAM 是**第一批**能被 Python 的
`MMIO` 直接触达的窗口。**⇒ C17 验的正是这个新能力本身**，不是旁枝。

**注意它不替代 C1–C16**：C17 只证明"Python 能读写缓冲、能让读取器动起来"；
**数据对不对、RF 口上有没有那个波形，仍由 C1–C4（示波器）与 C6–C7（片内回环）负责**。
**三层证据分开报，不合并。**

### 2.2 判据的仪器与工作点（按 `scope_limits.md` §7 的实测边界选）

- **时基**：`3.125 µs/div` —— 唯一同时给 2 GSa/s 与 62500 点的档，Nyquist 恰 1000 MHz
  （`scope_limits.md` §7.1）。**不用更短的档**：那些档悄悄缩短记录。
- **N 的取值**：`N ∈ {64, 128, 256}` ⇒ `Δf ∈ {937.5, 468.75, 234.375} kHz`。
  **不用更小的 `Δf`**：§7.3 实测分辨极限约 2 个 bin（2 GSa/s 下 ≈64 kHz），
  且 §7.6 记过 LO 泄漏在 LO 上恒有（`phase_inc=0` 时仍 +60.2 dB），近邻小 `Δf` 会被它淹。
- **判据一律用相对量**，不用绝对幅度：§7.5 证明 80–500 MHz 的幅度读数是**夹具**的
  （示波器只有 1 MΩ 输入，同轴未端接），跨频率幅度差不可归因。**C1–C4 全部是同频比较或频率位置比较，天然免疫。**
- **`scope_verify.py`/`scope_*` 纪律**：系统 `python` + `-u`；不写 `:WAV:POIN`；
  不绕过 `ReconnectingScope`；固定 `PROB=1`/`OFFS=0`。

### 2.3 两个 FIR 都开着 —— 这改变了 C6，但不改变 C1–C4

**板上实测（寄存器读回，非推测）**：`rf_main.c:849-852` **调用**了两个 FIR 的使能，但**结果不同**：

| 寄存器 | 读回 | bits[1:0] | 判定 |
|---|---|---|---|
| `0x002` TX_ENABLE_FILTER_CTRL | `0x52` | `0b10` = 2 | **TX FIR 开，插值 ×2** |
| `0x003` RX_ENABLE_FILTER_CTRL | `0x5C` | `0b00` = 0 | **RX FIR 关** |

位定义（`vendor/ad9361.h:603,616`）：
```c
#define TX_FIR_ENABLE_INTERPOLATION(x)  (((x) & 0x3) << 0)  /* Tx FIR Enable & Interpolation<1:0> */
#define RX_FIR_ENABLE_DECIMATION(x)     (((x) & 0x3) << 0)  /* Rx FIR Enable & Decimation<1:0> */
```

**RX FIR 没开成**，因为驱动把它判为非法并**拒绝**了，init 日志原文：
```
ad9361_validate_enable_fir: Invalid: ratio ADC/2 / RX_SAMPL * 16 > TAPS (max 64)
```
**⇒ `ad9361_set_rx_fir_en_dis(phy, 1)` 被调用了，但没生效。** 「调用」不等于「生效」——
这正是本项目「影子回读不证明生效」那条纪律的又一个实例。

**⚠ 同时更正规格文件**：`2026-09-17-ad9361-tx-bringup-design.md` §5.5 写的「TX/RX FIR 走旁路
（例程是开的）」**两边都不对**：TX FIR **开着且插值 ×2**，RX FIR **关着**。以板上读回为准。

**⇒ 两个后果：**

**(a) C6 的"逐位相同"不能无条件要求。** TX 链里有 **128 抽头 FIR + 插值 ×2**（所以 DAC 跑 120 MHz）；
RX 链**没有 FIR**，但有 HB 抽取链。若回环点在 TX FIR **下游**，取回的数据必然是被插值/滤波过的，
**要求逐位相同会得到一个假 FAIL**。

**⇒ 处置：把 C6 变成"看回环点在哪"的判别实验，两种结果都算 PASS，但结论不同：**

| `capdump` 与写入序列的关系 | 回环点位置 | 证据强度 |
|---|---|---|
| **完全逐位相同** | 在 TX/RX FIR **上游**（数字口直折） | **最强** —— 可逐位判数字通路 |
| **一致地等于某个已知 FIR 响应** | 在 FIR **下游** | 仍强，但须用**实测传递函数**做参考，不能要求原始比特相同 |
| **既不相同也不符合任何滤波器** | 帧/解串/字节序有问题 | **FAIL**，查格式 |

**这条本身就是一次判别实验，不需要额外步骤。**

**(b) C1–C4 不受影响，因为它们是频率判据。** 正弦过一个线性滤波器**仍是同频正弦**，
只是幅度与相位变了。所以：
- **C2/C3（`60e6/N` 的频率位置）** ✓ 不受影响
- **C4（单边带 vs 双边带）** ✓ 不受影响 —— I/Q 的**矢量关系**被同一个线性滤波器作用，
  单边带仍是单边带
- **C1 的 NV（缓冲全零 ⇒ 无谱线）** ✓ 零进零出
- **受影响的只有幅度类判据**，而本轮**刻意不用幅度判据**（§2.2，夹具问题）

**⇒ 这是"判据用频率不用幅度"这条选择的第二次回报**（第一次是免疫夹具）。

**另需在记录里写明**：本轮的 TX 波形**不是"样点直通 DAC"**，而是过了 128 抽头 FIR。
任何"我写进去的波形 = RF 口的波形"的说法都要加这个限定。

#### 2.3.1 C6 实测结果（2026-09-19 上板，**三轮修正后**）——**回环是双稳态的，好态逐位精确，坏态无法建模**

> **本节写过三个错误结论，三个的成因都保留，因为成因比结论更有用。**
>
> **第一版**记的是"I 恒为 0、捕获频率是发送的 2 倍、幅度 2032（TX 1500）"。
> **这三条没有一条是关于回环的。** 当时的步骤是 `smpcfg` → `init` → `regwrite 0x3F5 1 1`，
> 而 `init` **会复位芯片并清掉回环位**，`regwrite` 的掩码写当时又还没实现（直接整字节写）。
> 更要命的是 **`src_sel` 是 0** —— TX 源还指着 DDS，缓冲区**根本没被播放**。
> 于是那些数字描述的是"DDS 输出 + 上一轮实验残留在 BRAM 里的东西"，与回环无关。
>
> **第二版**记的是"8 字阶跃图案被扰动：9 个非零输出样本、逐点误差 ≤46 LSB"，与"冲激不展宽"
> 并列成一条**未解决的矛盾**，并把回环路径上的四个数字滤波器写成候选机制。
>
> **第三版（即上一版）把第二版那条观测"撤回"了，理由是"不可复现"。这个撤回本身是错的。**
> 当时的证据是"同一个 `diag_asym.py` 一字不改重跑 → 18 次捕获全误差 0，一次都没复现"。
> 但紧接着的下一轮实验立刻又复现了**同一个数（误差 46、同样那 9 个值）**，且 `diag_46.py`
> 连续 12 次捕获 **12/12** 全部复现，`diag_state.py` 在 `init` 之后 **3/3** 也复现。
> **⇒ 真相是"两态并存"，不是"一条假观测"。** 上一版拿一条干净连胜去否定一个间歇现象，
> 这是**从"没看到证据"推出"没有证据"** —— 判据的样本量不足以支撑"撤回"这个动作，
> 而"撤回"又恰好把唯一指向双稳的信号丢掉了。**记录两态、并写明开关未知**才是正确的写法。

**做对的步骤**（`rf_overlay/sw/loopback_criteria.py`）：`init` → 写缓冲 → `smpcfg` 提交
（提交要走 DATA_CLK，**时钟没起就锁不上**，所以必须在 init 之后）→ `srcsel 1` **并回读断言**
→ `regwrite 0x3F5 1 1` 开回环 → `capcfg`/`caparm` → `capstat` 见 `done=1` → 读原始字。

**⇒ 坏态下连"是什么"都说不出来**：见下。

**坏态的建模尝试（全部失败，这是坏态最有用的一条信息）**

| 候选模型 | 结果 | 脚本 |
|---|---|---|
| 纯旋转（整数 shift + 8 种符号交换） | **0 个精确解** | `fit_residual.py` |
| 旋转 + 插入/丢弃一个样本 | **0 个精确解** | `fit_residual.py` |
| **删掉捕获里任意一个样本**后重新求解 | **64 个删除位置全部无解** ⇒ 坏态**不是**"好态 + 一个多余样本" | `diag_shape.py` |
| ≤8 抽头**标量** FIR（每分量各一套抽头） | **无解** | `fit_residual.py` |

**⇒ 坏态不是一个定常线性滤波器。** 而且它**也不是**"好态加一个多余样本"——
两个最自然的解释都被排除了，这是坏态目前最硬的结论。

**⇒ 2026-09-19 晚：机制已定位 —— 坏态是 6 位半字错位，不是滤波器、不是延迟**

把 ASYM 捕获的 9 个非零字拿去拟合"**每个 12 位样点由相邻两个样点的两个 6 位半字拼成**"：

```
captured[k].I = high6(src[k-1].Q)*64 + low6(src[k].Q)
captured[k].Q = high6(src[k-1].I)*64 + low6(src[k].I)
```

（I/Q 交叉照旧；`high6(v) = v & ~0x3F`、`low6(v) = v & 0x3F`，两者相加**恒等于 v**，
所以"保持值精确"这一条自动成立，不需要额外解释。）**9 个实测字逐位全中、残差 0，
且 64 个 shift 里只有 1 个成立。** 包括那个"多出来的前导样本"—— 它就是 k=-1 这一行，
不是多余样本（这也正是"删掉任意一个样本"全无解的原因：它不在序列里，它在**行号**上）。

这一条把上面整张表的失败**一次性解释掉**：整数 shift 对不齐两个半字（`fit_residual` 无解）；
删一个样点也不行（64 个位置全无解）；2×2 矩阵 FIR 是**值**上的线性算子，而这个操作在**位**上
（所以残差停在 27.4 LSB 而不是 0，与"不是线性滤波器"的结论一致）。
冲激的 40/960 **不是** 1/25 与 24/25 —— 是 `high6(1000)*64 = 960`、`low6(1000) = 40`；
"整除 25"是 1000 恰好被 25 整除的巧合（`1000 = 8*125`、`40 = 8*5`），
所以那条"固定 0.96 样点分数延迟"的读法整个作废。
两个态的差别就是**两个半字是否取自同一个样点**。

RTL 上的落点：`phy_rx.v:201` 的 `{rx_data_shift_reg[23:18], rx_data_shift_reg[11:6]}`
把**两个不同 data_clk 周期**移进来的 6 位字段拼成一个样点，配对由
`rx_frame_shift_reg == 4'b1100` 的帧匹配选定 —— 帧相对数据偏一个周期就是坏态。
（`phy_rx.v` 是厂商代码；`rf_sample_capture.v` 只收 12 位整值、不做拆分，故拆分点在其上游。
`axi_ctrl` 只暴露了 `dclk` 计数，**没有暴露帧相位**，所以这条目前无法从软件侧直接观测。）

**⚠ 坏态不丢信息：这个映射是双射。** src[k] 的高半来自 captured[k+1]、低半来自 captured[k]，
所以**逐位反演可以完整恢复源序列** —— 实测 `half-model err = 0` 即等价于反演精确。
这一点直接改变 C12/C13/C16 的处境（见 §2.4.1 末）。

**⚠ 这一步差点又被一个假结果骗过去（方法教训，比结论更值钱）**：
把抽头数从 4 加到 16 时，残差下限在 **7 抽头处降到精确 0**，看起来像"找到了"。
**那是欠定拟合的必然结果，不是发现。** 8 字图案的捕获只有 **9 个非零样本 × 2 分量 = 18 个
独立数值**，而 K 抽头 2×2 矩阵 FIR 有 **4K 个参数**；K ≥ 5 时**参数比数据还多**，怎么都能拟合。
rank 列直接显示：13 抽头时 rank 40 对 52 个未知数，本就退化。
**⇒ 只有 4K < 18 即 K ≤ 4 才有判据价值，而在那一档残差是 27.4 LSB，不是 0。**
`diag_fit2.py` 现已把这条护栏写进输出（4K ≥ 18 的行直接标注
`UNDERDETERMINED -- fits by construction, not evidence`），并只报"确定"档的最佳拟合。
**这与本项目已有的两次同类错误是同一个形状**：判据无法通过（峰值归一化、纯音模型）
被读成通路有问题；这次反过来，**判据无法失败**（参数过剩）差点被读成通路被解释清楚了。

**⇒ 开关未知，就记作未知。** 本节能确证的是：**两态都真实存在、都可复现、态内确定**；
不能确证的是**什么在切换它**。把这个写成"已解决"或把坏态写成"已撤回"都是错的。
**但坏态**不是**什么，已经排除了两大类**：不是定常线性滤波器（≤4 抽头矩阵 FIR 拟合残差 27.4 LSB），
也不是"好态 + 一个多余样本"（64 个删除位置全无解）。

**⚠ "一次会话"是板子的上电/PL 状态，不是一个进程。** `Board.run()` **每条命令起一个新的
`board_app` 进程**（`loopback_criteria.py` 的 `Board.run` 注释里写着这条），所以 `diag_46` 的
"12/12"是**同一次上电内 12 次捕获**，不是 12 个会话。**⇒ `init` 就是重掷点（2026-09-19 深夜修正）**：
`diag_settle.py` 的 `init` 掷出坏态并稳定 746s；紧接着 `diag_invert.py` 的 `init` 掷出**好态**
⇒ **两次 `init`、两个不同态 ⇒ `init` 确实会重掷**，状态在**下一次 `init` 之前保持稳定**。
（`diag_state.py` 的 4 轮全坏只说明那 4 次都掷到了坏态，不说明"`init` 不能重掷"——那是把
"4 次没掷中"读成了"掷不动"，样本量 4。）
⇒ **要拿到坏态会话，重试 `init` 是有效手段**，这也正是 `diag_invert.py` 重试循环的依据。

**⚠ `diag_ab.py` 的"模拟路好态"这半句有判据缺陷，其排除结论不成立（2026-09-19 深夜复核）。**
模拟路的判据是**音调的 DFT 峰**（脚本 docstring 自己写着 *"exactness is impossible through both
128-tap FIRs, so only presence and frequency are judged"*）。而本机制是 **±63 LSB 的半字错位**，
在 1500 满幅的正弦上只有 ~4% —— **DFT 峰会照样又尖又准，判据结构上看不见它**。
那条排除的**逻辑前提**是"模拟路好态、数字路坏态 ⇒ 共用的部件被排除"；模拟路是否好态**没有验过**，
**前提不成立 ⇒ 结论不成立**，不能记作"捕获通路被排除"。
（**捕获通路另有独立排除**：`diag_buf.py` 的 `capdump`(C) 与 `rx_raw.py`(Python) 读同一缓冲
**0 处不一致** ⇒ 存储/读出不引入错位，**错位发生在捕获之前**。这比 `diag_ab` 那条更直接，
且不依赖模拟路的态。剩下待定的是**捕获上游**：FPGA 解串器 vs 芯片内回环路径。）

**⇒ 坏态模型再确认（2026-09-19 深夜，`diag_settle.py`）**：18 次捕获**全部** half-model err **0**，
且 18 次的拟合 shift **每次都不同**（48/34/43/63/7/30/45/41/40/60/13/42/48/25/50/40/45/58）——
**模型跟着自由运行的读取器走，而不是在拟合一个固定对齐**。这比单次 9/9 是更强的确认：
如果模型是错的，18 个不同对齐下同时凑出误差 0 是不可能的。

**回环路径上的滤波器寄存器读数**：

```
0x002 = 0x52  TX: TX_FIR ×2 插值 使能,  THB3 ×2 使能,  THB1/THB2 关
0x003 = 0x5C  RX: RX_FIR 关,  DEC3 ÷1,  RHB2 ÷2 使能,  RHB1 ÷2 使能
```

这些寄存器**确实**是这么配的（已读回）。但好态**逐位精确**，所以**不能**说这些滤波器
"串在回环路径上"；坏态又**拟合不出任何线性模型**，所以也**不能**说就是它们造成的。
**两个方向都不成立 ⇒ 这组读数目前只是事实，不构成机制。**

> 另注：`0x003 = 0x5C` 的 bits[1:0] = `00` 表示 **RX FIR 处于关闭**，而 `rf_main.c:932`
> 调的是 `ad9361_set_rx_fir_en_dis(phy, 1)`（开）。**2026-09-19 深夜查清：这不是硬件矛盾，
> 是"驱动自己拒绝了、而调用方没看返回值"。** 依据全在 vendor 源码（未改动）：
>
> 1. **位域确认**：`ad9361.h:616` `RX_FIR_ENABLE_DECIMATION(x) = ((x) & 0x3) << 0` ——
>    **bits[1:0] 同时携带"使能"与"抽取比"**：`0` = 关，`1/2/3` = ÷1/÷2/÷4
>    （`ad9361.c:5758` 写的正是 `(rx_fir_dec == 4) ? 3 : rx_fir_dec`）。
>    故 `0x5C` 的 bits[1:0]=`00` **确实**是"RX FIR 关"，上表的解码无误。
> 2. **这个 API 可以静默地什么都不做**（`ad9361_api.c:1128`）：
>    `if (phy->bypass_rx_fir == !en_dis) return ret;` —— **影子状态已符合就直接返回、一个字节都不写**；
>    若 `ad9361_validate_enable_fir()` 返回负，则 `phy->bypass_rx_fir = true;` —— **静默退回"旁路"**。
> 3. **两个调用点都丢弃返回值**（`rf_main.c:932` / `:1186` 都写作裸语句
>    `ad9361_set_rx_fir_en_dis(phy, 1);`）⇒ **拒绝是无声的**，板上没有任何地方会报出来。
>
> ⇒ **结论**：`0x003` 的读数是**唯一可信的状态**（RX FIR 确实关着），代码的"意图"不是状态的证据。
> 两个候选分支（影子状态已符合而早退 / 校验失败而回退）**可由一次 printf 分辨**：
> 打印返回值与 `phy->bypass_rx_fir`。**这是一个固件改动，未做**，记作可执行的下一步。
> 与之相关：`diag_fit2.py` 证明坏态**不是**短线性滤波器，所以"RX FIR 串进了回环"这条不成立；
> **但"RX 链实际只有 HB1+HB2(+DEC3)"这一点要写进捕获的解释里** —— 回环捕获看到的是
> 这条实际链，不是配置表里写的链。

#### 2.3.2 模拟回环（TX1A→RX1A 线缆）实测（2026-09-19 上板，**本轮新增**）

用户接上 TX1A↔RX1A 线缆后，**物理回环第一次打通**。这是与片内数字回环**完全不同**的一条路：

```
数字（0x3F5 bit0）  FPGA TX 数据 → FPGA RX 数据（数字口上原样返回）
模拟（本节的线缆）  FPGA TX → TX FIR ×2 插值 + 半带 → DAC → TX1A → 线缆 → RX1A
                    → RX 半带 + RX FIR(128 抽头) → ADC → FPGA RX
```

**⚠ 判据必须换**：两个 128 抽头 FIR 都使能（`rf_main.c:929-932`），所以模拟路的群延迟是
**几百个采样点**，**逐位判据在这里只可能 FAIL**，且失败不说明任何问题。
**能穿过这级滤波的只有单音**，所以判据是**存在性 + 频率跟随**（也正合本项目
「判据用频率不用幅度」的既有选择）：

| 观测 | 实测 | 判据 |
|---|---|---|
| **TX 全零 → 静默** | 峰值 189、rms 104、DC 26.3、DFT 峰仅 33.3 | 安静 ✓ |
| **TX 单音 k=1 → RX 峰在 bin −1** | `\|Z\|` 601.4（对比静默 33.3，约 18 倍） | 频率跟随 ✓ |
| **TX k=4 → bin −4** | `\|Z\|` 601.9 | 频率跟随 ✓ |
| **TX k=12 → bin −12** | `\|Z\|` 585.6 | 频率跟随 ✓ |
| **稳定性**（`diag_ab.py` 6 轮） | bin **恒为 −1**；`\|Z\|` 558→631 逐轮上升 | 稳定 ✓ |

- **`\|Z\|` 的 558→631 漂移是慢启动 AGC 在适应**（`gc_rx1_mode = 2`，`rf_main.c:289`），
  **幅度本来就不是判据**，故不影响结论。
- **符号翻转（TX `+k` → RX `−k`）与片内回环的 I/Q 交叉是同一件事的两种表现** ——
  两条完全独立的路给出同一个映射，**这是"RX 相对 TX 交换 I/Q"的第二个独立见证**，
  比单独一条更可信。
- **安全**：`init` 的 `atten` 默认是 **0 = 满功率直接灌进 RX1A**，直连线缆下必须显式给大衰减；
  本脚本用 **40000 mdB（约 40 dB）**。

**⇒ 模拟回环 PASS（存在 + 频率跟随）**。它证明的是**模拟链**（DAC/ADC/两路 FIR/AGC 都活着），
**不是"数据能不能回来"**——后者由 §2.3.1 的数字回环证明。
**⇒ 附带价值（本轮最有用的副产品）**：模拟路**好**而数字路**坏**，两者**共用** RX 捕获通路
（BRAM、捕获握手、`rx_raw.py`），**⇒ 捕获通路被排除**，坏态因此被定位到**数字回环自己的机制**上。

**⇒ C6 判 PASS，但 PASS 的范围要写清楚 —— 它覆盖"通路存在"和"映射"，不覆盖"逐位"**：

| 子命题 | 判定 | 依据 |
|---|---|---|
| 片内回环通路**存在**且数字域可读 | **PASS** | 两态都读到了与写入图案强相关的输出（好态逐位原样、坏态半位移且可逐位还原）；关掉 `0x3F5` bit0 后捕获**确实改变**（`diag_lb`：零图案 → 数字侧 0 个非零 / 模拟侧 64 个非零，**两侧都验了回读**）。原引的 NV2 那次**已撤销**（负控从未真正清零，见 §2.4.1） |
| 映射 = **I/Q 交叉**（非缺陷，是这颗芯片的既定行为） | **PASS** | 非对称图案 8 个字的 I 与 Q 互不相同，好态逐位对上交换后的图案 ⇒ 无串扰。**且 §2.3.2 的模拟路独立给出同一映射** |
| 延迟为**整数样点**（不插样、不丢样） | **PASS（两态）** | 好态：冲激 1 个非零样本、长度线性 1/2/4/8/16。**坏态同样成立**：冲激变 2 个样本**不是"插了一个样点"** —— 那一个冲激的高半落在 `captured[k+1]`、低半落在 `captured[k]`，半位移是**双射**，样点总数不变（§2.4.1 的 `unpair` 逐位还原，且相邻旋转被拒） |
| **逐位精确**（bit-exact） | **PASS（两态，具名）** | 好态逐位原样；坏态**由已知重配对逐位恢复**，C12/C13/C16 已在坏态判过且**解唯一**。原记 NOT RUN 的全部依据是"坏态无模型"——**该模型已找到**，见 §2.4.1 |

**⇒ C7 判 PASS**：判据的**原措辞**假设了不交叉，措辞作废；但**实质**成立 ——
非对称图案每个字的 I 与 Q 都不同，捕获逐位等于交换后的图案，有串扰就不可能对上。
**（C7 只在好态验过；它判的是映射，不是逐位，故不受坏态影响。）**

**⇒ 物理回环（SMA TX1A→RX1A）本轮已打通**（用户接线后），见 §2.3.2：
**存在 + 频率跟随 PASS**，证明的是**模拟链**，不是"数据能不能回来"。

**⇒ 坏态对本轮的净影响（2026-09-19 深夜更新：已消除）**：**没有阻塞 D1/D2 的结论**
（通路存在 + 映射成立）；原先**阻塞了"数据完整性"那一半**（C12/C13/C16），
原因是坏态**无模型**。**该模型已找到**（半位移、双射），C12/C13/C16 已在坏态判过且**解唯一**（§2.4.1）。
⇒ **"我写进去的样点会逐位从回环读回来"现在可以说**，条件是**写明是哪个态**：
好态逐位原样；坏态由已知重配对 `unpair` 逐位恢复。
**开关仍未找到，但它已不再阻塞这句话。**

#### 2.3.3 功分器：示波器与 RX1A 同时看同一路 TX（2026-09-20 上板）

用户在 TX 端加了**功分器**分成两路：一路给示波器、一路给 RX1A。这条改动的意义不是
"多一个观测点"，而是**两台互不相干的仪器第一次能对同一个 TX 状态作证**。

**⚠ 功分器不是保护**：两路功分器只带走约 3~6 dB，所以每次 `init` 仍显式给
**40000 mdB**。顺带修掉一处遗留：`loopback_criteria.py:397` 一直是 `init atten 0`
（满功率），那是线缆接上**之前**写的，接上之后就变成了危险默认；现改为
`SAFE_ATTEN_MDB`，依据是 C8 已实测数字回环捕获在 0/10000/30000 mdB 逐点相同
（回环点在衰减器上游），所以这个值取多少都不影响判据，取安全的那个不花代价。

**(a) 两台仪器互校（只有功分器才能做的一条）**
TX 是自由运行的 DDS（`srcsel 0`、`phase_inc 128`）。两台仪器读数相差数秒，但 DDS 是
稳态的，故可互校：

| 仪器 | 读数 | 换算 |
|---|---|---|
| 示波器（1 GSa/s，16 kHz 分辨率） | **81.8720 / 78.1280 MHz** | 相对 80 MHz LO = **±1872 kHz** |
| RX1A 捕获（`src_sel` 留在 0、回环关 ⇒ 只走线缆） | `\|Z\|` 峰 **bin 2**，`\|Z\|`max **23190**，次峰仅 **264** | bin 宽 937.5 kHz ⇒ **1875 kHz**；1872 kHz 落在 bin 1.997 |

两个数字**单位不同、分辨率差三个数量级、各自独立**（示波器在 RF 域，RX 在 60 MSPS
抽取后的基带），一致到 RX 的 bin 宽以内 ⇒ **模拟腿 + 功分器 + RX 捕获通路确实都看着
同一个发射机**。

**⚠ 这一条我第一版做错了，且错得很难看**：直接用了 `capture()`。而 `capture()` 结尾
**总要断言 `src_sel = 1`**，于是 TX 被切到**缓冲区**（而它又先清零缓冲区）——读到的
"RX 眼里的 DDS"其实是"RX 眼里的静音"，频谱一片平（1318/1290/1194/1064，无主峰），
**看上去像一个很像样的负结果**。修法是手工走同一套序列、但把源留在 DDS 上。

#### 2.4.3 2R2T 下 C10–C16 **判不了**：那条路**从不加载 IDELAY**（2026-09-20 上板）

`loopback_criteria.py` 加了 `--phy-mode 2r2t` 之后首轮上板，C10/C14/C15 照常通过，
C11/C12/C13/C16 **一个精确解都没有**：

```
C11/C12 exact: []   best (1102, '-i,+q', 19)
C13  D=1/2/4/8/16 best err = 1100/551/275/241/136，0 解
C16  best err 2075，0 解        NV2 best err 1014
```

注意五条各自的最佳映射**互不相同**（`-i,+q` / `+i,+q` / `+i,-q` / `+q,-i`）——
"映射不同"会给出**同一个**映射，四处不一致是"**根本没对上**"的签名。
而同一脚本同一天在 1R1T 是逐位精确的（§2.4.2）。这不是判据回归，根因在**结构**上：

| 事实 | 出处 |
|---|---|
| IDELAY 的**唯一**写入者是 `plcfg` | `rf_main.c:669-670`（`EN 0x7F` / `TAP 15`） |
| `plcfg` 的**第一件事**就是把 `phy_mode` 写成 1 | `rf_main.c:668` |
| `init` 只写 `PHASE_INC` 与 `PHY_MODE`，**从不碰 IDELAY** | `rf_main.c:869-875` |
| 回环是 **AD9361 的 data-port 回环**（SPI `0x3F5` bit0），不是 PL 内的数字环 | `rf_main.c:619` 用法说明；`capture()` 的 `regwrite 0x3F5 1 1` |
| 所以返回路径**要穿过物理 LVDS DDR 引脚**，经 `phy_rx.v` 的 IDELAYE2 | `phy_rx.v:79/139/143`（`LD(idelay_en[i])`） |

⇒ **2R2T 流程里谁都不写 IDELAY**（`plcfg` 被跳过，因为它会强写 `phy_mode=1`），
`idelay_en` 恒 0、IDELAYE2 从没被 load，RX 引脚按原语上电 tap 采样。
**这不是 2R2T 的特点，是"跳过 `plcfg`"的代价。**

**A/B 对照**（同一位流、同一块板、相隔几分钟，一次只改一个变量）：

| 条件 | 结果 |
|---|---|
| 1R1T，`idelay_en = 0x7F`，tap 15 | **逐位精确 3/3**（唯一解 `('+q,+i')`，shift 9/37/46） |
| 1R1T，`idelay_en = 0x00`，tap 15 | **9/64 样点偏离，最大 46**（连零样点都读成 (36,40)） |
| 2R2T，`idelay_en = 0x00` | best err **1102**，0 解（首轮失败即此） |
| 2R2T，`idelay_en = 0x7F`，tap 15 | 映射回到 `('+q,+i')`，残差塌到**一个样点的一位** |

**还查清了一半、留了一半**：2R2T 加载 IDELAY 之后，图案 `(-500, 700)` 的 I 读回 **-372**
（`0xE0C → 0xE8C`，恰好 bit7），**确定性重现**、不随 tap（5..19 的结果**完全相同**）、
不随重测变化。TX 缓冲回读确认写进去的就是 `0x02BC0E0C`（I=-500 Q=700）⇒ **不是写入路**。
tap 扫描 `0/3/5/7/8/9/11/13/15/17/19/23/27/31` = `1200/2/128×11/1664/1663/帧检测失败`：
**tap≥23 时 `rx_frame` 过不了 `1111`/`0000` 判别，`done` 永不来**（`phy_rx.v:200/204`）。
**为什么剩下的是一位错——未查清**，不写成结论。

**结论**：2R2T 下 C10–C16 标 **NOT RUN**（既不 FAIL 也不 PASS）：判据自己指出它在这条路上
测不到东西。要判 2R2T 的样点路，先得让这条路能加载 IDELAY —— 把 `plcfg` 的 IDELAY 写入
从 `phy_mode` 写入里**拆出来**，或给 `board_app` 加一个独立子命令。**本轮不做**。

#### 2.5.1 C5 与 C1 载体两条 N/A 的复查（2026-09-20 上板，`rf_overlay/out/diag_floor.log` + `diag_c1_scale.log`）

C 层现况是 `=== 7 PASS, 0 FAIL, 2 NOT-APPLICABLE, 2 RECORD-ONLY ===`，两条 N/A
（**C5 衰减差**、**C1 carrier**）都记作"仪器所限"。本轮把这两条各测到底，结论是
**两条 N/A 都保留，但理由都换了**，且 C5 的判据本身有一处缺陷。

**（1）C5：它的判据输入是"一个来回摆 14 dB 的量"的一次抽样。** 固定工作点
（atten 60000 mdB、0.5 V/div）连采 8 帧，78.128 MHz 边带 bin 相对噪底中位数的读数
是 **1.0 / 1.8 / 9.3 / 15.7 / 10.3 / 11.5 / 14.9 / 12.9 dB** —— 跨度 **14.7 dB**，
6.0 dB 的可测性门禁 **8 次里过了 6 次**。套件那句"the tone at 60000 mdB reads 5.7 dB"
就是这个分布里的一次抽样，所以 **C5 现在的 N/A 是掷硬币，不是对板子的陈述**。
（同一批数据里 argmax 选的"最强非 LO 线"在 500 / 250 / 125 / 31.5 / 16.8 / 10.8 / 3.5 MHz
之间乱跳 —— 这正是 `scope_tx_check.py:1130` 那段注释警告的 argmax 缺陷，本次是它的实测复现。）

**（2）40000 点是稳的，60000 点根本没测到音。** 同一脚本内交错四块
（A: 40000、B: 40000 再来一次、C: 60000、D: 40000），各 8 帧：

| 块 | atten | bin 读数（均值 / 8 帧） | 噪底绝对值 | 峰值码 | 波形 std |
|---|---|---|---|---|---|
| A | 40000 | **25.7 dB**（25.1–27.2） | 47.0–47.7 | 131 | 0.65 |
| B | 40000 | **25.4 dB**（24.0–27.3） | 47.1–47.7 | 131 | 0.65 |
| C | 60000 | 7.4 dB（**−5.7 … 15.4**） | 47.0–47.8 | 131 | 0.66 |
| D | 40000 | **26.6 dB**（25.8–27.7） | 46.9–47.7 | 131 | 0.66 |

40000 点在 24 帧里稳定在 **25.4–26.7 dB**；60000 点连平均值都不稳（两次运行
8/16 帧均值分别是 7.4 与 11.4 dB）。**关键是 C 块的噪底绝对值、峰值码、时域 std
与 A/B/D 逐位相同** —— 20 dB 衰减步进连波形 std 都推不动（0.65 → 0.66），说明
60000 点测的是噪底自身的起伏，不是音。因此 40000→60000 这一对**无法测出它自己的
20 dB 步进**，且**平均也救不了**（平均只能把单帧的掷硬币变成稳定估计，而估计本身
是带噪底偏置的，两次运行的 7.4 / 11.4 就是证据）。

**（3）衰减器本身是好的。** 已接受的 stage-1 记录里 C5 在 **10000→30000 mdB 实测
19.85 dB**（`docs/rf/l2_stage1_record.md:270`）。所以 40000→60000 读不出 20 dB 是
**测量**（上端落进噪底），不是器件。

**（4）C1 carrier：N/A 是诚实的，但理由要从"噪底淹没"改成"窗口里是真线"。**
在套件的 0.5 V/div 下，±250 kHz 窗里的冠军 **12 帧只有 1 帧**落在 80.0000 MHz
（其余在 79.856–80.192 之间跳），中位领先 **0.3 dB** —— 冠军是噪底极大值，与
`find_carrier` 注释记录的 2026-09-20 现象一致。把垂直档位改到 **0.02 V/div**
（峰值 148/255，**不削顶**）后，冠军 **12/12 帧都精确落在 80.0000 MHz**，幅度
18.2–23.1 dB（正是 `FIX_CARRIER_SNR_DB` 注释记录的载体带 17.3–21.2 dB）—— 载体
**确实存在且可识别**。但它的领先量只有 **2.5–5.2 dB（中位 4.3）**，从未达到 6.9 dB，
且窗口里的亚军在 14–20 dB，**是真线不是噪底极大值**。故 `find_carrier` 的判决
（"没有一条突出到可称载体"）**是对的**，只是 0.5 V/div 下它给出的这个结论碰巧与
0.02 V/div 下的一致而**理由不同**。

**（5）两条都不可由"只改测量"收口，且都不该靠放松门限收口。**
- C5 要能被判，只能把这一对下移（见下），或者按（2）如实记 N/A 并写明理由；
- C1 carrier 的 6.9 dB 门限是**预先注册**的（`CARRIER_MARGIN_MIN_DB` 注释：载体
  17.3–21.2 vs 噪底极大值 7.6–10.5），而 0.02 V/div 下窗口里的亚军是 **14–20 dB 的
  真线** —— 判据的前提群体与今天的邻线不是一个东西，**换档位就必须重新推导门限**，
  不能拿旧门限套新群体。

**（6）该判据还有一处独立缺陷待修**：C5 的可测性门禁（`snr_high < PEAK_SNR_MIN_DB`）
拿**单帧**做判决，而该量单帧摆 14 dB（见（1））。门禁本身的方向对（上端确实在噪底
里），但它需要多帧估计才配得上"measured, not chosen"这个说法。

#### 2.5.2 §2.5.1 的收口：C5 判据改写（2026-09-20 实现 + 首轮上板；判决见 §2.5.3）

§2.5.1（5）给出的两条出路里，**取"把这一对下移"**，门禁按（6）改成多帧估计。两处
改动都经用户批准后才动，理由是 §2.5.1 那六条实测，不是偏好。

**改动（`rf_overlay/sw/scope_tx_check.py`）**

- 新增 `ATTEN_FLOOR_MIN_MDB = 20000`：**本脚本任何 `init` 允许的最低衰减**。它替代
  原先那句 `all(a >= SAFE_ATTEN_MDB)` 的守卫下限——那条守卫在 `ATTEN_LOW_MDB = 20000`
  下必然失败，把它删掉等于把守卫悄悄放宽到"脚本恰好发了什么"，所以改成有界且显式：
  守卫查 `>= ATTEN_FLOOR_MIN_MDB`，另加一条断言把 `ATTEN_FLOOR_MIN_MDB == 20000`、
  `SAFE_ATTEN_MDB == 40000`、以及 C5 这对**恰好**落在两端钉住。20000 不是新工作点：
  它比已接受的 stage-1 那一对（10000→30000，实测 19.85 dB）还高 10 dB。
- C5 这对改为 `ATTEN_LOW_MDB = 20000` / `ATTEN_HIGH_MDB = SAFE_ATTEN_MDB = 40000`，
  上端正好落在安全底；判据是**差**，两端一起平移不变量不变，所以只有可测性受影响。
- 新增 `C5_CAPTURES = 8` 与 `avg_capture(capture, channel, n)`：**RMS 型**平均
  （`sqrt(mean(s_i^2))`），不是幅度均值。选 RMS 是因为下游全是 `20*log10`：相干线各帧
  同幅，RMS 等于该幅度（读数与单帧可比）；噪底是起伏的，RMS 的 `20*log10` 才是它的功率
  估计，而幅度均值会取到 Rayleigh 分布的均值（中位数的 1.25 倍），**给整套 dB-above-floor
  数字无端加上约 2 dB 偏置**。`capture` 作参数传入，沿用 `layer_c` 已有的注入点。
- C5 两点都改走 `avg_capture`；C6 是同两次捕获的副产品，自动跟着变，公式不须动。

**顺带查出的两个测试缺陷（都是"测试一直在靠运气过"）**

- `_planted_spectrum` 的 `exact` 邻居上限原为 `amp * 0.5`，即**恰好 6.02 dB 的领先**，
  正落在 `CARRIER_MARGIN_MIN_DB = 6.9` 的判决区内。改用 `amp * 0.1`（20 dB）：该上限
  存在的理由只是"让植入的那格仍是局部极大值"，0.5 与 0.1 都满足，而 0.5 会让一个只想
  测 SNR 门的 fixture 被边沿门共同裁决。
- `_gate_fixture`（测 `CARRIER_SNR_MIN_DB` 的那个）**实际是被边沿门决定的**：实测
  `gate + 1` 那一档返回 N/A，因为窗口里 **80.2240 MHz 处一个噪底极大值量到 8.8 dB**，

#### 2.5.3 §2.5.2 的收口：`init` 会清零 `phase_inc`，C4/C5 都拿它当了理由（2026-09-20 已修 + 上板 PASS）

**症状与证伪顺序**（每一步都排除了一个嫌疑，剩下的才是根因）

1. **仪器无罪。** 重启后 C5 报 `measured difference = -1.07 dB`，上端仅 10.1 dB above floor。
   先把示波器状态回读做了一遍，与套件自己的设置**逐项相同**（`SCAL 0.5`、`PROB 1`、

   131、std 0.65）。→ 断电重启是清白的。
2. **`avg_capture` 无罪。** 配置正确时单帧与 RMS 平均一致（20000 mdB 下 45.2 vs 44.9 dB；

## 4. 重建预算与重建后门禁

**本轮预算：一次重建。** 理由：XDC 修复（§1.7）与 BD 改动（§1.2）**互相依赖**——
BD 新增的读取器活在 `data_clk` 域，若约束仍是 4 倍宽松，**新逻辑无论多慢都会报 MET**，
本轮的全部时序证据就是空的。所以两者必须在**同一次**重建里生效，不能拆成两次
（拆开的话第一次重建的时序结论无意义）。

**重建后三条门禁全绿才准上板**（沿用 `plan:840-843` 的 R7）：

1. `.bit` 与 `.hwh` 的 mtime **都晚于** `create_bd.tcl`；
2. `check_status_reg.tcl` 打印 `STATUS-REG-OK` —— 且**本轮要扩展它**：现有判据只查
   STATUS 寄存器 cell 数与 `phy_mode` 网的路数（`:18-34`、`:57-76`），**看不见新加的存储器**。
   必须加断言：**两个 `blk_mem_gen` 实例、两个 `axi_bram_ctrl`、以及 TX 读取器与 RX 采集器
   的 cell 在已路由网表里都存在**（并断言各自的 RAMB 计数 > 0，即 §K2 的空网表陷阱）。
   **理由就是它自己的 header（`:4-7`）写的**：本项目有过"manifest 哈希对、逻辑却来自更旧
   `create_bd.tcl`"的前科，**时间戳看不出来，只有打开网表找新版本独有的 cell 才知道**。
3. 构建日志无 `ERROR`；**且时序报告要按新的 `data_clk` 周期读**（2R2T 240 MHz），
   若 `data_clk` 域出现违例，**停下来修 RTL，不许放宽周期**。

**另需**：按 `CLAUDE.md` 的 IP cache 陷阱，改动 `blk_mem_gen` 参数后若出现"配置改对了却仍报
存储器缺失"，先 `rm -rf` 对应 `rf_overlay/vivado/rf_overlay/rf_overlay.cache/ip/<ver>/<hash>/`
再重建（纯派生产物，安全）。**两级 BRAM 门禁**（`tools/check_bd_bram.tcl`）在 RF 侧不存在，
本轮不强行搬（它硬编码了 `awg/` 与 `host_bd`）；改为**用 §4 门禁②的网表断言**覆盖同一风险。

- **不改 AD9361 采样率**：60 MSPS 是规格与例程值，且是常驻指令下的默认

## 6.5 RX 采集与片内回环（2026-09-19 用户裁决加进本轮）

### 6.5.1 为什么加它：它是**测量仪器**，不是**交付物**

§3.3 写「**明确不要求**：RX 通路」。加它的理由不与之冲突，因为**它不是本轮要交付的功能，
是本轮要用的量具**。它换来的东西很直接：

- **D1/D2/D4 从"示波器看频谱变了"升级到逐位比对** —— 12 位、全速率、逐样点，不受
  示波器 8-bit 与 100 MHz 前端的任何限制。
- **关闭 M4**（`usability_assessment.md` §4.1 记「高（验收哲学层面）」）：原文是
  "AWG 的验收靠**闭环 + 相对量**。RF 后端没有 RX 就无法闭环自证，只能靠外部仪器"。
- `backend_contract.md` **R7 本来就是为环回写的**（"同板环回只验证**相对**频率"）——
  说明环回早就在契约的考虑里，不是新发明。
- 迁移阶段的 BER 有了地基。

### 6.5.2 好消息：RX 的 PL 前端**已经在位流里**

`ad9361_phy` **已经**把解串后的样点输出到端口（`ad9361_phy.v:35-40`）：

```
output adc_d1q1_valid, adc_d2q2_valid
output [11:0] adc_data_d1, adc_data_q1, adc_data_d2, adc_data_q2
```

BD 也把 `rx_clk_in_*` / `rx_frame_in_*` / `rx_data_in_*` 都接到引脚了（`create_bd.tcl:74-85`）。
**LVDS 采集、IDELAY、帧对齐、解串这一整套最难的部分已经在验证过的 `ad9361_phy` 里了。**
**唯一缺的是：`adc_data_*` 这几个输出悬空，没接到任何地方。**

RX 的射频侧也已经在配：`ad9361_set_rx_sampling_freq(60 MSPS)`、`ad9361_set_rx_lo_freq(同一个 LO)`、
`rx_bandwidth = 30 MHz`（`rf_main.c:886 / 906 / 252`）。

### 6.5.3 片内 TX→RX 回环：**已查清，可以直接调 `ad9361_bist_loopback(phy, 1)`**

`ad9361.c:1085` 的 mode 1 是"AD9361 internal TX→RX"。它的实质是写
`REG_OBSERVE_CONFIG`(0x3F5) 的 bit0 `DATA_PORT_LOOP_TEST_ENABLE`。

**查证链**（这一节是为了不重犯"凭代码名断言"的错）：

1. `vendor/config.h:66` → `#define AXI_ADC_NOT_PRESENT` **是开的**。
2. `ad9361_conv.c:49` 的 `#ifndef AXI_ADC_NOT_PRESENT` 有 `#else` 分支（644–678）。
   宏开着 ⇒ **走 `#else`**，所有用 `axiadc_*` 的正文**根本不参与编译**
   —— 这就是它在 `sw/board_app/` 里"只有声明没有实现"却仍能链接的原因。
3. `#else` 分支给的 stub（`ad9361_conv.c:651-654`）：`ad9361_hdl_loopback()` → `return -ENODEV;`，
   **不碰任何寄存器**。
4. `ad9361_bist_loopback` mode 1 调它时**丢弃返回值**，随后只做 **SPI 读-改-写**
   （`REG_PARALLEL_PORT_CONF_3` 读、`REG_OBSERVE_CONFIG` 写）。
   `ad9361_int_loopback_fix_ch_cross`（`ad9361.c:1066`，未被宏关掉）在 rx/tx 通道号相同时
   直接 `return 0`。

**⇒ 全程只发 SPI，不碰 AXI、不碰 PL、不用电缆、不用示波器、不动增益。**

**⚠ 两个坑：**

- **绝不用 mode 2**（"FPGA internal RX→TX"）：它唯一的动作是 `ad9361_hdl_loopback(phy, true)`，
  而那是个 stub ⇒ **静默无效且不报错**。这正是本项目最怕的形状。
- `ad9361_int_loopback_fix_ch_cross` 在 **rx/tx 通道号不同**时会调 `ad9361_en_dis_tx`
  **关掉一个 TX 通道**。默认两者都是 1（`ad9361_api.c:525-527`），但**开之前要运行时确认**。

### 6.5.4 一个必须实测、不能断言的问题：这个回环是**数字**还是**穿过模拟**

寄存器名 `DATA_PORT_LOOP_TEST_ENABLE` 听着像纯数字口回环，**但不能凭名字断言**。

**判别实验（判据 R1）**：回环开着，改 `tx_attenuation_mdB`（例如 10000 → 30000），看回环
收到的样点幅度：

| 观测 | 结论 |
|---|---|
| **幅度不动** | 纯数字回环（在 DAC 之前折回）⇒ 它**只**能证数字通路，模拟口仍须靠示波器 |
| **幅度跟着变** | 穿过了模拟链 ⇒ 它同时也证了一部分模拟通路 |

**这条实验的结论要写进记录**，因为它决定片内回环的**证据强度边界**——不写清楚，
后面就会有人拿它当"RF 也验过了"。

### 6.5.6 可配置抽取器（2026-09-19 用户裁决）

**为什么必须可配置**：被评的外部设计文档（`docs/rf/channel_ai_assessment.md` §5.1）要**同时**做
"窄带主导"与"宽带噪声主导"两类判别，而**这两个需求在窗口上互相拉扯**——单一固定配置满足不了：

| `decim` | 实际采样率 | 4096 点的窗口 | **数字复基带 Nyquist 区间** | 适合 |
|---|---|---|---|---|
| 1 | 60 MSPS | **68.267 µs** | **−30 ~ +30 MHz**（总跨 60 MHz） | 宽带噪声、脉冲 |
| 2 | 30 MSPS | 136.533 µs | −15 ~ +15 MHz | |
| 4 | 15 MSPS | 273.067 µs | −7.5 ~ +7.5 MHz | |
| 8 | 7.5 MSPS | 546.133 µs | −3.75 ~ +3.75 MHz | |
| 16 | 3.75 MSPS | **1.092267 ms** | −1.875 ~ +1.875 MHz | **窄带、慢衰落** |

**⚠ 三个"带宽"必须分开说，不许混为一谈**（2026-09-19 外部计划 §3.1 的更正，成立）：

| 名称 | 值 | 是什么 |
|---|---|---|
| **数字复基带 Nyquist 区间** | ±30 MHz（总跨 **60 MHz**） | 60 MSPS 复采样决定的，表里这一列 |
| **RX 滤波带宽设置** | 30 MHz（`rf_main.c:252` 的 `rf_rx_bandwidth_hz`） | 驱动写进 AD9361 的**滤波器**参数，另一回事 |
| **实际可用通带** | **未测** | 受滤波器、模拟链、抽取共同限制 |

**三者数值接近纯属巧合**（Nyquist 与滤波器带宽都约 30 MHz），**但它们不是同一个量**。
抽取后 Nyquist 变成 ±1.875 MHz，而**滤波器带宽仍是 30 MHz 没变** —— 于是
**1.875~30 MHz 的能量会折叠进观察带**，这正是下面第 1 条要处理的。

**实现**：D 个连续复样点求和、除以 D（D 是 2 的幂 ⇒ **算术右移，无乘法**）。

**三条如实说明**（第 1 条已按外部计划 §3.2 更正 —— 我原先写的"能量类特征无影响"**是错的**）：

1. **boxcar 对时域统计和频域统计都有影响，而且它不是充分的抗混叠滤波器。**
   `y[m] = (1/D)·Σ x[mD+k]`。独立零均值白噪声、忽略量化时，**输出噪声方差变成输入的 1/D**；
   窄脉冲被**展宽／削弱**；**峰均比、峭度、过阈占空比都会变**（D 点平均趋向高斯 ⇒ 峭度往 3 走）。
   **⇒ 没有任何特征类可以在不同 D 之间无校准迁移。抽取比是特征的一部分，不是透明的预处理。**

   **❌ 我原先的写法**：「能量类特征（平均功率、PAPR、峭度、削顶比例、突发占空比）无影响」
   —— **这六项里有五项是错的**（平均功率变、PAPR 变、峭度变、占空比变、削顶统计变）。

   **混叠补不回来**：带外分量折叠进观察带，而**简单除以 sinc 不能恢复已经混叠的信息**，
   靠近零点的补偿还会**放大误差**。所以"补偿"只能修**带内滚降**，修不了折叠。
   只有实测表明当前方案不满足目标，才增加更好的抗混叠滤波 —— **不提前扩成复杂 DDC**。

   **处置**：每个 D **单独标定**特征，或把 `decim` 作为**显式条件输入**。
   训练与推理必须匹配 `decim`／滤波配置／采样率／增益／特征版本。**一套配置一个模型**是可接受的起点。
   外部计划 §3.2 提了一条**值得采纳的补充**：若要在抽取后仍保留脉冲／削顶信息，
   **在抽取前加少量计数器（峰值保持＋过阈计数）** —— 那正是 boxcar 会毁掉的东西，而计数器很便宜。
   本轮**记为可选补充**，不默认做。

2. **截断偏差**：对有符号数做算术右移是"向下取整"，不是"四舍五入"，偏差 ≤ 0.5 LSB。
   对判别特征无关紧要，但**写进记录**，不假装它是精确平均。

3. **`rx_len` 计的是抽取后的样点数**，不是字节数、也不是输入样点数。
   `rx_len=4096, decim=16` ⇒ 覆盖 65536 个输入样点 = 1.092267 ms。
   **这一点不写清楚，窗口长度会被算错 16 倍。**

4. **有限快照有大段观察空隙，且必须记录**（外部计划 §3.4 的更正，成立）。
   100 ms 抓一次 1.09 ms ⇒ **覆盖率约 1.1%**，99% 的时间是盲的。
   **不能证明捕获到了稀疏脉冲，也不能把不连续窗口拼成连续 IQ。**
   必须记录采集间隔、覆盖率与事件漏检。**这条对 "脉冲主导" 这个标签是致命的**，
   要让下游知道该标签的证据强度受限。**不用 DMA 是本轮的架构选择，不是"能保证捕获任何事件"。**

**负例（`PASS NV`）**：`decim` 改变时，**同一段信号**的窗口时长必须按表变化；若窗口不变，
说明抽取器没生效（或 `rx_len` 数错了）。**另一条**：同一段白噪声在 D=1 与 D=16 下，
**平均功率必须不同**（差约 10·log₁₀16 = 12 dB）——若相同，说明抽取器没生效或特征算错了口径。

**与 TX 侧的对称性**：TX 是"PS 写 A / PL 读 B"，RX 是"PL 写 B / PS 读 A"。
**同一个 BRAM 范式，方向相反**，不引入任何新的存储/DMA 概念。**不开 `S_AXI_HP0`，不用 DMA。**

## 7. 本轮之后仍未决的（交给下一阶段）

1. **迁移阶段（M1/M2）的速率方案** —— 用户已选「60 MSPS（按规格，需 5/6 转换）」。
   但**本轮实测出第三条路值得在迁移阶段重估**：把 AWG 链时钟改为 **`DATA_CLK/2` = 60 MHz**
   （PL 内从 DATA_CLK 派生），则**精确 1:1、不需要 5/6 插值器**，而链参数重算的代价
   与「50 MSPS 捷径」是同一笔 —— 用户选"按规格"时已经接受了那笔重算。
   **记在这里，不在本轮实施。**
2. **连续流式驻留**必须开 `S_AXI_HP0` + DMA，且要先解 `CmaFree = 3.5 MB`（`backend_contract.md:169`）。

4. **E6**（任意波形下的示波器边界，`scope_limits.md` §4.7）以本轮为放行条件 —— 本轮过掉后可以开始。
