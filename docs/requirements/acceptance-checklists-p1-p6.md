# P1–P6 验收清单（六类门）

> **开发部署与最终验收分开使用**：2026-10-17 起，审查轮数与开发版安装前置按[个人开发审查与部署规则](development-review-policy.md)。本清单保留最终功能验收目标；未执行的正式采集或真人项不阻塞范围明确的实验候选安装。

日期：2026-10-14（P0 Task 1.3）。约定：每个 Chunk 进入下一阶段前，本表对应行的"六类门"必须逐项有证据或明确 `NOT_RUN`；**失败与未知保留**，不得改写成通过。状态词与 `docs/requirements/brief-traceability.md` 第 1 节相同。

六类门固定为：**离线（OFF）→ ARM（ARM）→ 数字回环（DL）→ 有线物理（PHY）→ 真人（HUM）→ 发布（REL）**。某类不适用时写 `N/A` 并说明原因，不写"通过"。

## 0. 通用规则

1. 任何一类门开始前，先有**该类的预声明判据**（阈值、场景、失败定义）；判据写在采数之前。
2. 板卡运行前必须有：只读预检（发布/服务/存储/RF safe）、人工接线记录、一次性授权（如涉及 RF 发射或物理研究）、独立安全读回。
3. 测试数量不能替代物理或真人结果；历史收据只证明其版本与范围。新改动补齐受影响的验证，未受影响的证据和覆盖同一差分的独立审查可以引用，不要求全链重审。
4. 每行证据必须可指向：命令、原始退出码、收据文件 SHA-256、必要时原始 IQ 路径。

## 7. 更新规则

- 每完成一项，把"当前状态"改为对应状态词，并在证据列（后续按需加列）写命令/收据路径与 SHA-256。
- 同一 ID 的状态只能由新证据升级；任何回退（例如发现旧证据无效）必须保留原状态与原因。
- 新增发现（新负控、新失败模式）应新增 ID，而不是改写已有 ID 的判据。
