# Lane1 tap30 残差后的推进建议

依据 DSH 2026-10-26 11:11 结束记录。本对话未连接板卡、未采集、未安装、未修改产品。

## 已确认的进展与限制

- 已安装 6384a07e2d7d135bfb021b9ac75f337f；最后读回 RF 关闭、全部 IDELAY 配置127/29、boot bc500450-18d4-408b-8955-43e8f6e57a51。
- 同会话基线有241个 bit 事件；lane1 tap30两帧分别165、178个事件，仍非零。C帧是177个错误样本对、178个事件，不能把178当成错误样本对。
- frame-only25可复现采集超时，data-only25/27/30/31并未复现同类超时；两个失效模式应分开处理。
- 重复29/30可以研究相对收益，但不能消除已有错误；下一轮优先定位接收数字链路残差，停止局部tap扫描。
- 同码不同输出只反对无上下文的固定码值映射，不能排除具有前后文/状态的数字逻辑缺陷。简单模数直方图没有尖峰，也不能排除所有frame/valid机制。

## 下一轮建议范围

1. 复用 `evidence/codex-frame-idelay-check-20261025/verification.json` 的bit载荷/DCP关联，不重做历史来源审计。
2. 用已验证的Vivado 2025.2读取同一routed DCP，导出lane1与其他数据lane对照：RX IBUFDS/IDELAY/IDDR/两半字装配/BRAM位对应，TX ODDR/OBUFDS/转发时钟对应。数字data-port回环覆盖TX与RX，不能把RX改tap有收益当作排除了TX侧。
3. 检查实际端接、IDDR/ODDR模式、时钟边沿、有效输入输出延迟、例外覆盖。当前源码IBUFDS字面DIFF_TERM=FALSE与rf.xdc端口TRUE存在文本差异，应读实际实现属性，不能凭源码任一侧宣布实际值。
4. 从项目内原始参考或官方一手资料取得AD9361数字接口时序及相位约定；未知板级skew标明假设和敏感性，不填写无来源的外部延迟来让报告变绿。
5. 将准确串行协议变成独立参考激励，复用现有UNISIM和最小测试台，不按接收输出反推期望。验证连续I/Q序列、符号跳变、多个起始相位以及wire到参考IQ映射。
6. 发现可复现的RTL/约束缺陷再做最小补丁和相关验证；本轮允许一次必要的离线硬件重建，产生有输入来源和时序覆盖说明的新候选，安装前仅做一次关键差分审查。未找到依据时明确列出缺失的模型/时序参数，不堆计数器、不再采同样失败帧。

只审本次RF串行接口，不修无关AWG/LCD历史告警。不启动新的板端研究、安装或默认参数更改。
