## 独立交叉重放

脚本及结果：`evidence/codex-qam64-v2-fresh-negative-20261025/cross_replay.py`、`cross-replay.json`。v1、v2 在独立 Python 子进程导入各自冻结 release，避免模块缓存混用；两批各 19 个输入摘要、共 38 次核对全部匹配。

|---|---:|---:|---:|---:|
| 第一批 A | 2 | 0 | 511.551 | 77.591 |

v2 对第二批 B 的归一化对齐残差 RMSE 约 1.048，第二批 A 约 0.453；B 校正矩阵条件数约 1.085，没有出现明显病态。两批四个 ON 的窗口内 RX gain index 都为 76，芯片 TX 衰减读回均为 `[46000,46000]`。四个 ON 的 TX load amplitude 都为 60，长度 2540 samples / 10160 bytes，wrap=true，payload SHA 都是 `8a118d01f0f277ad49cf2abb9bd72b0e7408dda5fd07594a391851e0c58ecb61`。

结论：现有数据没有证明 v2 比 v1 退化；v2 改善了全部四个保存的 ON 样本，但无法消除新 B 的错误。新 B 的信号幅度指标显著下降，而归一化误差增大，应优先检查信号链/采集状态变化，而不是直接推出新的算法版本。

不能仅凭这些指标把原因定为 AGC、某个模拟器件或热漂移；归一化残差也不等于已经测得纯噪声 SNR。单次 gain index 与 attenuation 读回不能代表窗口内完整增益/幅度轨迹。

## 可复用的已有诊断接口

现有 `rf_status_client.py` 的物理 capture 已允许 `observe_timing` 和 `settle_wait_us`，上限 **5000 us**；非零等待要求 `observe_timing=true`。`rf_daemon.c` 在 TX source 已开启后、RX prepare/arm 前执行该等待并记录 timing brackets。

因此可在不修改 daemon、RTL 或安装候选的条件下，准备一项固定 0/5000 us 的诊断对照。不能把主机在发命令前 sleep 当作 TX-on 窗口内等待，也不能把 5000 us 写成 5000 ms。先核对实际冻结 release 与 daemon 既有能力，再由 runner 明确传参并保留可验证的原始时序。

## 建议的下一工作包

优先完成离线源链核对、样点/符号幅度与残差分布，查看 B 的幅度下降是全窗口稳定存在、突发变化还是局部污染。所有新拟合仍只用对齐区，不依比较区误码挑参数，旧结果不覆盖。

若仍不能离线定位，可由用户明确授权一批小型稳定性诊断：**2 sessions / 2 init / 2 loads / 6 ON TX / 10 captures / 0 retry，总墙钟计划≤180秒，capture deadline 10秒**。每个 session 只初始化、加载一次，在同一 session 内复用波形，不为每帧重新初始化。

- Session 1：OFF → ON(wait=0 us) → ON(wait=5000 us) → ON(wait=0 us) → OFF。
- Session 2：OFF → ON(wait=5000 us) → ON(wait=0 us) → ON(wait=5000 us) → OFF。

其他条件固定为当前 80 MHz / 46 dB / amp60 / 60 MSPS / 3 Msym/s / 4096 / RECT / QI / seed39。两种等待均记录真实 timing。平衡顺序用于减少单调漂移与先后顺序的混淆；两次初始化不足以建立总体统计结论。

比较每帧幅度、归一化对齐残差、相邻电平判决裕量、增益/衰减、请求身份和 v1/v2 同 IQ 误码；检查同一初始化内部及不同初始化之间的差异。OFF 的窗口内物理观察可以缺失，但不得伪造；ON 的实际物理观察和时序仍须可用。非零 BER 是数据，不因其重试或停止后续合法测量；结构/安全/身份/收尾错误按预写停止条件处理。

先验证 runner 的多帧单次 setup、实际参数传递和收尾假链，由 Lead 做一次相关增量自检即可。本建议不是对尚不存在 runner 的代码批准，也不是 RF 操作授权。实际执行授权可由用户复制给 DSH 的提示词给出；不得从本报告自行推导。
