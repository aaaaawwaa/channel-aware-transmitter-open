# 触摸界面与数据有效性

## 分层

UI视图负责绘制/事件；模型负责草稿、状态与合法动作；worker串行执行控制/采集/分析；client负责协议与超时。不要从绘制回调直接MMIO、重载Overlay或启动另一个硬件拥有者。

板端触摸应用与PC串口上位机是不同产品入口。屏幕上“应用草稿”“加载成功”“实际发射”和“历史接收结果”应清晰区分。显示标签不能替代实测。

## 帧身份与失效

用实际协议提供的发布、配置修订、连接代次、采集身份与IQ摘要关联结果。独立会话可能重用短capture_id，归档时不能仅以该字符串去重；同时保留会话路径/摘要。

新配置、停止、断线、发布变化或清除快照时，使当前分析失效。历史图/BER可保留为历史，但不得显示为新帧的成功结果。缺失解调结果不是OFF通过，模型预测正确也不是参考同步或BER通过。

## 性能与观测

- PS端测整条处理路径的延迟分位数与RSS，记录输入长度、采样率、算法/权重版本；不把独立小探针性能替代实际产品路径。
- PL职责、PS职责和离线分析结果分别说明。界面上的理想星座、合成波形与接收IQ星座不同。
- UI离线测试可验证按钮/失效/线程边界；真人屏幕验收另记，不预填通过。录屏/照片可能包含设备标识，分享前检查。
- 模型未经校准的得分不称为可信概率；未知/域外输入显示拒绝原因，不据发射设置倒推出接收或环境识别成功。

## 常见定位顺序

画面不变先查是否收到新结果及渲染签名；按钮无响应先查在途状态与门禁原因；控制可达而采集缺失时区分能力接口，不因某个未接入功能把整个后端标离线。不要通过删门禁、自动回落模式或显示旧值来“修好”界面。
